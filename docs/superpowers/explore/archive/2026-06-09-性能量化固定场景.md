# 性能量化固定场景

日期：2026-06-09
状态：active

## 目的

固定场景用于让性能优化、代码重构和回归检查使用同一套操作路径。不同操作路径的日志只能做趋势参考，不能作为严格回归结论。

## 通用采集配置

```text
qm_perf_debug 1
qm_perf_logfile 1
qm_perf_debug_threshold_ms 4
```

## 场景

| ID | 操作路径 | 主要归因 | 失败信号 |
| --- | --- | --- | --- |
| PERF-SETTINGS-TEE-SWITCH | 打开 Settings，切到 Tee 页，等待首屏稳定 | page_switch、section、work_drain | p99 > 16ms 或连续长帧 |
| PERF-DEMO-FIRST-ENTER | 首次进入 Demo Browser，打开含大量 demo 的目录 | page_switch、list_frame | 单帧 > 33ms 或 list_frame 无 rows_skipped |
| PERF-SERVER-SCROLL | 进入 Server Browser，滚动一屏 | list_frame | rows_iterated 明显大于 rows_rendered，或 rows_rendered 明显大于 rows_visible |
| PERF-ASSETS-DRAIN | 进入 Assets / Workshop，等待缩略图和资源完成 | work_drain、device | 交互帧无 stop reason 的集中 publish |
| PERF-TEE-SCROLL | Tee 页快速滚动一屏 | list_frame、work_drain | 已显示 preview 回退到 loading 或 drain 无预算原因 |

## 报告要求

- 保存 HTML report、`*_summary.json` 和固定名 `perf_summary.json`。
- 写明客户端版本、renderer、窗口模式、刷新率、UI scale。
- 对比官方 DDNet 或上一轮 QmClient 时，必须说明 operation signature 是否一致。
