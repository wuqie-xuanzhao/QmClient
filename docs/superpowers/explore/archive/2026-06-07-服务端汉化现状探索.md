## 速答

当前服务端里确实还有很多硬编码英文，而且已经不是“纯英文待汉化”的状态，而是**英文为主、局部已混入中文**的混合态。只看主要玩家可见文案密集区，`src/game/server/gamecontext.cpp`、`src/game/server/ddracechat.cpp`、`src/game/server/scoreworker.cpp`、`src/game/server/teams.cpp`、`src/game/server/ddracecommands.cpp` 这 5 个文件里，就能直接搜到约 946 处英文字符串字面量命中；其中不少是聊天、广播、帮助文本、排行榜/存档结果和队伍状态提示，玩家会直接看到。

但这批字符串不能无脑“一次性全部改中文”。原因有三点：

1. 服务端已经存在一个**局部汉化钩子**：`ConHelp` 会把命令帮助文案通过 `LocalizeChatHelp()` 走 `languages/simplified_chinese.txt` 做查表翻译，因此命令 `Help` 描述天然适合保留英文 key，再补语言表。
2. 还有很多玩家可见文案根本**不走本地化层**，而是直接 `SendChatTarget` / `SendBroadcast` / `Console()->Print("chatresp", ...)` 发裸字符串；这类如果要汉化，只能改代码字面量，或者额外引入新的服务端本地化机制。
3. 服务端里还有一部分英文并不是玩家 UI 文案，而是**管理端/调试/日志/协议相关文本**。这些未必应该改中文，否则会降低服务器运维、日志搜索、上游对齐和排障可读性。

如果目标是“先把普通玩家最常看到的服务端英文改成中文”，最适合的第一批是：

- `ddracechat.cpp`：`/settings`、`/times`、`/top5team`、`/practice`、`/swap`、`/team` 等聊天命令反馈；
- `scoreworker.cpp`：排行榜、个人成绩、checkpoint、存档查询结果；
- `teams.cpp`：换队、swap、成绩反馈等队伍私聊提示。

而 `gamecontext.cpp` 中的 `Console()->Register(..., "Help text")` 更适合走“补翻译表，不改英文 help key”的路径，不建议直接全部改成中文字面量。

## 后续建议

如果后续真的要开始“服务端汉化”，建议先拆成两个批次：

1. **玩家提示批**：先处理 `ddracechat.cpp` / `scoreworker.cpp` / `teams.cpp` 里最常见、最确定会显示给玩家的反馈文案。
2. **帮助文本批**：单独整理 `gamecontext.cpp` 里的 `Console()->Register(..., Help)` 英文 key，优先补语言表并验证 `/help` 输出，而不是直接把 help key 改成中文。

管理日志、调试输出、SQL 语义字符串和运维控制台文本建议最后再评估是否需要汉化，不要和第一批混做。
