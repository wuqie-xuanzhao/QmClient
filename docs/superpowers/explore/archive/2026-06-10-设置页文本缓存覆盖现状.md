# 设置页文本缓存覆盖现状

## 速答

P0-A 不需要新建一套文本缓存系统。当前仓库已经有 `SettingsTextElement()`、`DoSettingsLabelStreamed()` 和 `CUIElement::SUIElementRect` 文本容器复用路径，但覆盖面很窄，主要集中在 General 页标题、Language 列表和少数 TClient/QmClient helper。

更关键的是，`perf/section` 的 `text_new` / `text_reused` 字段格式已经存在，但当前没有看到 `m_pActiveSettingsTextPerfStats` 在 section 或页面渲染作用域中被挂载。因此 P0-A 的第一步应该先让统计真正覆盖可验证的设置页渲染作用域，再分批替换静态 `DoLabel(&Rect, ...)` 为 `SettingsTextElement()` + `DoSettingsLabelStreamed()`。

## 关键证据

1. `SettingsTextElement()` 已按 `Page + Tab + TextId` 建立稳定 `CUIElement` 池，并在语言文件或自定义字体变化时清空池。证据：`src/game/client/components/menus.cpp:3720`、`src/game/client/components/menus.cpp:3724`、`src/game/client/components/menus.cpp:3730`。

2. `DoSettingsLabelStreamed()` 已经能通过 `pTextContainerRecreated` 统计新建/复用次数，但只在 `m_pActiveSettingsTextPerfStats != nullptr` 时累加。证据：`src/game/client/components/menus.cpp:3740`、`src/game/client/components/menus.cpp:3744`。

3. `CUi::DoLabel(const CUIRect*, ...)` 仍走 immediate 文本路径，每次计算布局并 `TextEx`，不复用 `STextContainerIndex`。证据：`src/game/client/ui.cpp:840`、`src/game/client/ui.cpp:852`。

4. `CUi::DoLabelStreamed(CUIElement::SUIElementRect&, ...)` 会比较文本、尺寸、颜色和 read cursor 状态，只在变化时重建 text container。证据：`src/game/client/ui.cpp:884`、`src/game/client/ui.cpp:889`、`src/game/client/ui.cpp:910`。

5. `perf/section` 日志格式已经有 `text_new` / `text_reused` 字段，但当前只看到格式和 source-contract 测试，没有看到 active stats 作用域挂载。证据：`src/game/client/components/menus_settings.cpp:633`、`src/game/client/components/menus_settings.cpp:644`、`src/test/qmclient_monitoring_test.cpp:442`。

6. 设置页相关文件仍有大量未缓存 `Ui()->DoLabel(&...)`：`menus_settings.cpp` 约 66 处、`tclient/menus_tclient.cpp` 约 97 处、`qmclient/menus_qmclient.cpp` 约 141 处。证据来自 `Select-String -Pattern 'Ui\(\)->DoLabel\(&'` 的文件分组统计。

7. 已缓存示例说明局部迁移模式稳定：General 页标题已使用 `SettingsTextElement()` + `DoSettingsLabelStreamed()`；Language 列表也在 cache path 下复用 language filename 作为 key。证据：`src/game/client/components/menus_settings.cpp:708`、`src/game/client/components/menus_settings.cpp:770`、`src/game/client/components/menus_settings.cpp:4328`。

## 结论

P0-A 的正确边界是扩大现有缓存入口覆盖率，而不是引入新 UI 框架或 retained-mode 文本层。第一批实现应优先处理静态标题、静态说明和稳定 label，避开动态值、输入框内容、hover-only tip、会按帧变的状态文本和列表项值。

验收上不能只看源码替换数量。必须先补 active stats 作用域，让 `text_new` / `text_reused` 在至少 General、TClient、QmClient 页面路径上能真实反映缓存命中情况。
