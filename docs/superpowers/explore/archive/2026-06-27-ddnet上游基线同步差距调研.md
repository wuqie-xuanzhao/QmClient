### 战略级决策：snapshot Rust 化

> 用户认同 Rust 方向，但要求"保证当前构建能正常运行、客户端游玩不出问题；若是开发中版本则留后面"。

**是什么**：把网络快照的构建（building）+ 增量（delta）用 Rust 重写，复用 heinrich5991 的成熟库 `libtw2`（`libtw2_snapshot`），通过 cxx bridge 暴露给 C++。动机是**健壮性**（内存安全 + 复用验证过的实现），非性能。规模 +5806/-831：新增 ~725 行 Rust（builder.rs/delta.rs/mod.rs/uuid_manager.rs）+ ~5000 行 C++ bridge（`rust-bridge/cpp/*`），删 623 行旧 `snapshot.cpp`，引入 libtw2 crate 依赖。

**官方 Rust 化策略**：DDNet 的 Rust 化是**有选择性的**——只对计算机网络相关、安全性/健壮性要求高的模块迁移到 Rust，不是全盘 Rust 化。snapshot building/delta（网络快照核心路径）和 uuid_manager（网络对象类型识别）正属此类，故优先 Rust 化并复用成熟的 `libtw2`（Teeworlds 协议 Rust 实现）。这是 heinrich5991 主导的长期方向。**对 QmClient 的含义**：跟 Rust 化 = 跟"网络/安全模块"的演进；而 UI/编辑器/渲染等非网络模块上游仍是 C++，QmClient 在这些区域的维护压力不会因 Rust 化而增加。

**成熟度核实（2026-06-27）**：

- ✅ **已进入 DDNet `19.9-rc1` release tag** —— 不是 WIP/实验性，是上游确定的稳定方向（PR #11957，主体 commit `a1e9d2b3c8`，2026-04-16 落地，至今经历 405 个提交演进，已过危险期）。
- ⚠️ **Rust 化初期暴露过 bug，上游已修**：`d125ad6201`/`f02c17a673`（snapshot pool invalid item id 崩溃）、`2ecaaf638a`/`8611c684a4`（sixup ID 重复）。要合必须连这些后续修复一起带上，否则踩坑。
- 构建门槛：要求 **Rust 1.85+**，CMake 会检测 rustc 版本（`a4dd3b943d`/`03c77ae831`）。

### SDL3 迁移深入评估

> 用户问"迁移 SDL3 的意义"。SDL3 是 SDL2（维护 10+ 年、技术债重）的主版本重启，SDL 3.2.0 已正式 release。

**核心改进**：

| 领域 | 改进 | 对 DDNet/QmClient 的意义 |
| --- | --- | --- |
| **SDL_GPU** | 全新跨平台 GPU 抽象（D3D12/Vulkan/Metal/OpenGL） | 看情况：QmClient 已有 graphics 抽象层，SDL_GPU 多半不直接用 |
| **HiDPI** | **默认 DPI 感知**（SDL2 要手动 opt-in） | **最实际**：高分屏（4K/Retina）渲染/缩放痛点直接改善 |
| **音频** | logical audio devices + streams | 更灵活的音效/音乐/语音分离 |
| **输入** | 更好的键盘/手柄/摇杆 | 手柄支持增强 |
| **长期** | SDL2 进入维护模式，新平台/硬件只在 SDL3 | 早晚要跟的根本原因 |

**现状**：`#9622` 仅 edg-l 意向（原文 "I'll look into it."），1.5 年没动，无计划/PR。**成本高**（窗口/事件/音频/输入 API 破坏性重构），但有官方 **SDL2-compat** 兼容层（用 SDL3 后端跑 SDL2 API）可渐进过渡。

**时机**：现在不急（上游都没启动），但 HiDPI 痛点 + SDL2 长期停演进，意味着 1-2 年内要提上日程。**一句话**：意义在 HiDPI 立竿见影 + 长期不掉队；SDL_GPU 锦上添花不一定用。
