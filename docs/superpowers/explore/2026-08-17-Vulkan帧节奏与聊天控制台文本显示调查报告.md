# 结论摘要

1. Vulkan 提交链已明显改善，Apple/MoltenVK 单线程录制当前保留，数据正常。
2. 输入“慢一拍”的直接原因已确认：MoltenVK 无 MAILBOX，上次回退到 FIFO；`vkQueueSubmit` 每帧约 9.7ms 被垂直同步阻塞。
3. 非垂直同步下的闪烁/顿挫**可以继续用代码修**，但不能靠 IMMEDIATE/MAILBOX 二选一硬切；下一步应做“present 与主循环解耦 + FIFO_RELAXED/帧节奏”。
4. 系统/echo/F1 文本问题**不是 Vulkan 丢绘制**：Vulkan 文本计数器全为 0，文本容器有效且已上传；问题在 CPU 侧的聊天行准备和 F1 控制台滚动/裁剪逻辑。
5. F1 表现为“滚动时临时显示、停下后消失”，且丢失的是进游戏前的旧信息，强烈指向控制台 `m_BacklogLastActiveLine` / `m_BacklogCurLine` 的渲染窗口计算。

# 已经落地的修改

文件：`src/engine/client/backend/vulkan/backend_vulkan.cpp`

1. **延后下一帧准备**
   - `m_FramePrepared` 状态机。
   - `NextFrame()` 只提交/present 当前帧，不再在 Swap 尾部执行 `PrepareFrame()`。
   - 下一份命令缓冲首条命令进入 `RunCommand()` 时，才 acquire、等 fence、开 render pass。
   - 目的：让主线程先把下一帧命令缓冲交给图形线程，减少尾部串行等待。

2. **Apple/MoltenVK 强制单线程录制**
   - vendor 为 Apple 时 `m_ThreadCount = 1`。
   - 避免 MoltenVK/Metal 对 secondary command buffer 的高编码开销。
   - 新日志 `thread_record=0`，渲染稳定，暂不撤销。

3. **macOS 非垂直同步呈现模式**
   - 当前顺序：`MAILBOX -> IMMEDIATE`。
   - 原因：MAILBOX 不可用时继续回退 FIFO，会让 `vsync=0` 变成事实上的垂直同步，输入被压到 100Hz。
   - 风险：IMMEDIATE 会带回闪烁/撕裂，见下文待办。

测试文件：`src/test/qmclient_monitoring_test.cpp` 已同步调整 source contract。

# 非垂直同步闪烁/顿挫：是否可修

可修，但方向不是继续在 MAILBOX 和 IMMEDIATE 之间二选一。

当前事实：

- MoltenVK 没有 MAILBOX。
- FIFO 平滑但阻塞提交，输入延迟。
- IMMEDIATE 输入快，但无垂直同步，画面会撕裂/闪烁，游戏内帧节奏随 CPU 抖动而顿挫。

下一会话优先做：

1. **记录可用 present modes**
   在 `GetPresentationMode()` 打印 MoltenVK 实际支持的完整模式列表，确认是否有 `FIFO_RELAXED_KHR`。

2. **优先 FIFO_RELAXED**
   若存在，`vsync=0` 建议顺序：
   `MAILBOX -> FIFO_RELAXED -> IMMEDIATE`
   FIFO_RELAXED 比 FIFO 更适合低延迟输入，比 IMMEDIATE 少闪烁。

3. **真正解耦主循环与 present 阻塞**
   当前 `CGraphicsBackend_Threaded` 只有一份在途命令缓冲；Vulkan 的 `vkQueueSubmit` 阻塞会传导到主循环。
   下一阶段应增加 2~3 份 in-flight 命令缓冲，让 present/acquire 的等待发生在图形线程内部，而不是每次 Swap 都让主线程等待。
   这是解决“既要有垂直同步的平滑，又要有低输入延迟”的底层方案。

4. **IMMEDIATE 帧节奏兜底**
   如果短期仍使用 IMMEDIATE，应把 `gfx_refresh_rate` 自动对齐 `gfx_screen_refresh_rate`，避免 500Hz 提交到 100Hz 屏幕造成显示节奏抖动；但这只是缓解，不能消除撕裂。

# 系统/echo/F1 文本问题定位

Vulkan 已排除。下一会话从 CPU 侧布局/滚动窗口修，不要继续改 Vulkan 文本路径。

## F1 控制台

现象：
- 滚动过程中能暂时看到部分旧内容。
- 停止滚动后，进游戏前的内容消失。
- 稳定时只显示底部两行。

重点代码：
- `src/game/client/components/console.cpp:2596-2597`
  `m_BacklogLastActiveLine = m_BacklogCurLine`
- `src/game/client/components/console.cpp:2624`
  `if(LineNum < m_BacklogLastActiveLine)`
- `src/game/client/components/console.cpp:2652-2653`
  `CanRenderOneLine` 与 `Outside` 的提前 break。
- `src/game/client/components/console.cpp:2874`
  渲染结束后把 `m_BacklogLastActiveLine` 写回 `m_BacklogCurLine`。

推测：停止滚动后 `m_BacklogLastActiveLine`/`m_BacklogCurLine` 形成错误的“只渲染底部窗口”；旧 entry 在 `LineNum < m_BacklogLastActiveLine` 分支被跳过，或在 `Outside && !CanRenderOneLine` 提前 break。拖动滚动条时临时改变了这些值，所以内容短暂出现。

下一会话第一件事：修控制台 backlog 滚动窗口状态，确保静止时也按当前滚动位置渲染完整可见区间。
