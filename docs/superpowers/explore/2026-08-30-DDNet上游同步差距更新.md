# DDNet 20.0 上游同步差距更新

> 本文是当前活动校对报告。旧版 `docs/REPORT.md` 和归档报告只保留历史背景，不作为当前合并依据。

## 1. 结论先行

- 官方 `20.0` tag 为 `a5a61806e434`；官方 `master` 当前为 `1f9b18961549`，`20.0..master` 为 **243 个提交**。
- QmClient 当前 `HEAD` 为 `14ef8c4c7`，仍使用 `GAME_RELEASE_VERSION_INTERNAL 19.9`。因此不能称为“官方 20.0 完整快照”，但已经吸收多批 20.0 之后的实际代码。
- 本轮最新的 5 个真实行为提交已经完成本地适配并提交：无设备音频、投票回收、地图声音错误状态、音频断言和 WavPack UBSan 抑制，见 `14ef8c4c7`。
- 128 人支持主体已经在更早的本地历史中大规模完成。本报告不把它重新列为待实现功能；后续只验证混合会话、SeeOthers 和 timeout reconnect。
- “剩余工作”必须分三类：
  1. 已合并代码但缺设备、服务端夹具或人工 smoke 证据；
  2. 需要独立平台/策略决定的延期批次；
  3. 只有在运行时验证暴露真实缺口时才新增的补丁。

## 4. 对官方 20.0 发布日志的核对

官方发布日志中的功能在 QmClient 的当前状态应这样理解：

| 发布日志范围 | 当前判断 |
|---|---|
| `[Server] 128 player support` | 主体早已完成；只剩混合协议和真实 128 人运行时验收。 |
| `[Client] Web version` | QmClient 当前没有可用 Emscripten HTTP backend；不从桌面 curl 路径硬套，列为 Web 独立批次。 |
| `[Editor]` tabs、多地图状态和 envelope 修复 | 多地图状态、editor tabs 及本地修复已存在；只补确认缺失的行为，不重做 QmClient UI 架构。 |
| Android aim-relative joystick/direct input | 属于 Android 输入运行时范围；现有通用触控/输入代码不能替代设备 smoke，需单独验证实际手势。 |
| off-screen culling、scoreboard/text cache、hook/telehook 和 projectile clipping | 逐项源码审计后按等价覆盖或本地适配处理；不因官方主题相同就重复 cherry-pick。 |
| Dynamic antiping、demo player data、snapshot item 对齐和包大小校验 | 属于预测/协议/快照边界，已有本地兼容路径；任何剩余差异须单独测试，不能用 128 人完成度代替。 |
| Editor component、brush、quad、map validation | 已吸收明确的崩溃、边界和状态修复；视觉行为仍需 editor smoke。 |
| Server SSL MySQL、rescue/swap、snapshot purge、version prefix | 需要分别核对 QmClient 数据库、玩法和版本策略；版本号不在本报告中擅改。 |
| `[Infra.]` settings 拆分、popup 文件、macOS packaging | 代码/资源拆分按 QmClient 所有权适配；不直接搬迁官方 CI 或发布工作流。 |

结论是：发布日志是功能索引，不是可直接执行的 cherry-pick 列表。QmClient 的 128 人、iOS、网络和 editor 路径存在大量本地重构，必须按行为和兼容性判断。

## 5. 当前仍缺的内容

### 5.1 已有代码，缺运行时证据

这些项目不是等待重新实现的功能：

1. **iOS P3C**：本机没有已安装的 iOS simulator runtime；尚无默认 asset catalog 构建、simulator 安装/启动、GLES、触控、联网、后台恢复、截图、Files export、退出和真机 smoke 证据。
2. **0.6/0.7/128 混合会话**：需要旧客户端、新旧 server、SeeOthers 和 timeout reconnect 的真实夹具；不能用单元测试或 128 人源码主体替代。
3. **网络资源预算**：需要 Linux Valgrind integration 和高并发压测；当前 C++ 回归只证明边界和合同。
4. **Econ/HTTP 生命周期**：需要可控 fake HTTP/job 或 TCP reconnect 夹具，验证退出并发和重连时序。
5. **地图/编辑器/音频视觉 smoke**：需要真实地图、音频设备和 editor UI 场景；构建不能代替人工行为验证。

### 5.2 明确延期的独立代码/策略批次

| 项目 | 延期原因 |
|---|---|
| Emscripten HTTP 系列 | 当前没有对应 backend；需连同 Web 构建链、线程取消和 HTTPS 策略成组实现。 |
| Vulkan HDR/headless 等能力扩展 | 不是当前 20.0 桌面同步必要条件，需独立能力矩阵和视觉验证。 |
| DSCP EF/TOS 策略 | 当前 QmClient 仍有跨平台 LOWDELAY/qWAVE 语义；这是 QoS 策略变化，不应无确认替换。 |
| `NET_MAX_PAYLOAD` 重命名 | 涉及协议命名和兼容边界，需原子批次处理。 |
| 翻译刷新 | `translations/i18n/*.toml` 是维护源，生成语言文件不能直接作为 cherry-pick 产物。 |
| Node.js/CI action、20.1 版本策略 | 属于 CI/release 决策，不是当前客户端代码缺口。 |

## 7. iOS Metal 结论

### 7.1 当前事实

- iOS 平台本身支持 Metal，Apple 的承载方式是 `CAMetalLayer` 或基于它的 Metal view。
- QmClient 当前 iOS 适配仍使用 SDL/OpenGL ES；现状不是目标状态。新的适配目标是让 macOS 和 iOS 的默认 `Release` 构建都编译并打包 Metal，GLES 只作为显式回退。
- 当前 macOS Metal backend 位于 `src/engine/client/backend/metal/backend_metal.mm`，使用 `SDL_MetalView`、`CAMetalLayer`、drawable/present、Metal shader 资源和 macOS CMake 条件；这些条件必须扩展为可验证的 Apple 共用路径，而不是直接复制 macOS 假设。
- iOS Metal 仍不能直接复制 macOS backend：view/layer 生命周期、shader SDK、feature set、后台恢复、旋转和 device/simulator 产物都要独立适配。

### 7.2 需要独立处理的移植面

1. UIKit/`CAMetalLayer` 的 view 生命周期、旋转和 drawable 尺寸变化。
2. drawable 获取、present、后台/前台恢复、窗口 resize 和设备丢失。
3. shader/metallib 编译、bundle 资源复制和 iOS framework 链接。
4. render target、MSAA、readback、截图和纹理格式能力协商。
5. iOS device 与 simulator 的 feature-set 差异，以及 arm64 真机和模拟器验证。
6. 与现有 SDL/OpenGL ES 后端并存时的 backend identity、设置项、构建开关和回退策略。

### 7.3 建议结论

后续按 `docs/superpowers/plans/2026-09-01-QmClient-iOS-Metal默认Release适配计划.md` 执行：先完成 Apple 默认 Release 的构建接线和 iOS shader 产物，再按 backend 生命周期、资源能力、绘制/readback、simulator/device 验收分阶段推进。不得把 macOS Metal 已经能编译或能运行当作 iOS Metal 已完成；在真机证据齐全前，GLES 回退必须保留。

官方参考：

- Apple `CAMetalLayer`：https://developer.apple.com/documentation/quartzcore/cametallayer
- Apple Metal：https://developer.apple.com/documentation/metal
- SDL Metal backend：https://github.com/libsdl-org/SDL/blob/main/src/gpu/metal/SDL_gpu_metal.m

## 8. 最终合并建议

1. 当前代码合并批次先以 `14ef8c4c7` 收口，不再重复实现 128 人主体。
2. iOS 代码主线按 Metal 默认 Release 计划推进；有 simulator runtime 后优先完成 Metal bundle/启动合同，再做混合 0.6/0.7/128 验收；只对实际失败行为新增补丁。
3. 再做 Linux Valgrind、高并发、Econ/HTTP fake lifecycle 和地图/editor/audio smoke。
4. Emscripten、Vulkan 能力扩展、DSCP、翻译、CI 和版本号按独立决策批次处理。
5. 只有完成适用运行时验收并形成 release plan 后，才考虑把 `GAME_RELEASE_VERSION_INTERNAL` 升到 20.0。

## 9. 工作树边界

当前工作树仍有 Metal、菜单/UI、统计、翻译、CMake 和测试等其他任务改动。本次代码合并提交只包含各自列出的文件；没有使用 `git add .`、`git reset --hard` 或覆盖并行修改。后续任何构建都必须先检查后台的 CMake/Ninja/Xcode/Cargo 进程，并在同一 build 目录串行执行。
