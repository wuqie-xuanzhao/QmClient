# 皮肤列表稳定态性能安全性收口报告

## 结论

本轮收口针对设置页 Tee/皮肤列表非冷启动、长期停留时可能稳定掉到 80 多 FPS 的结构性风险。修复重点不是提高预算，而是移除稳定态无效全量工作，并补齐对应 telemetry。

## 已收口

- Tee 列表预扫描新增 `tee_skin_list_prescan`，并停止在 pre-scan 中为全量 skin 构造 preview cache key。
- ready 语义拆分为 visual ready 与 source settled；后台 drain 和 high-priority settled 只使用 source settled。
- background candidate scan 增加 complete/list-size 状态；一轮扫完没有 `UNLOADED` 候选后，后续稳定帧不再继续全表扫描，且不再用全局 unloaded 统计打脏过滤列表。
- `CSkins::UpdateStartLoading()` 不再做 unordered_map fallback sweep，加载推进只走 usage/background 显式队列；保留 `skin_start_loading_fallback_sweep` telemetry 口径用于确认 fallback 未启用。
- 新增结构测试覆盖上述约束，防止回退到稳定态每帧 O(total) 扫描。

## 验证关注点

真实采集时应重点看：

- `tee_skin_list_prescan` 的 `dur_ms` 与 `items_scanned`。
- `tee_skin_background_scan complete=1` 后 `items_scanned` 不应每帧保持全量。
- `skin_start_loading_fallback_sweep` 在 idle 稳定态应不触发。
- `IDLE_DRAIN` 只应在 visible source settled 后进入。
