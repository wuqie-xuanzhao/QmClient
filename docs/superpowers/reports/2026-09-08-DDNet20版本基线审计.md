# DDNet 19.8-20.0 版本基线审计

日期：2026-09-08

## 审计范围

核对 DDNet 19.8、19.9 到 20.0 的官方版本边界与提交状态，逐项对照当前 QmClient 分支。仓库没有 `19.8` tag，因此以官方 `f9e69715f`（`Bump dev version to 19.8`）作为 19.8 边界。官方历史在 `19.9-rc1` 分叉出 beta 线和发布线：beta 线到 `f82770664`（`Bump beta version to 20.0`）有 565 条提交，发布线到 `20.0` tag 有 808 条提交；两条线共享 `19.9-rc1`，不能简单相加为单一线性范围。每条提交分为：原样合入、本地适配、功能等价、明确未合入、版本或发布策略不适用。

## 当前基线结论

- 当前 `src/game/version.h`：`DDNET_VERSION_NUMBER 19090`、`GAME_RELEASE_VERSION_INTERNAL 19.9`。
- 当前 `QMCLIENT_VERSION`：`3.0.2`。
- 仓库存在官方 `20.0` tag，但 `20.0` 不是当前 `HEAD` 的祖先；不能把当前分支称为完整 DDNet 20.0 基线。
- DDNet 19.9 同步提交 `ed2e89fde`、`aec0a1370` 已在当前祖先链中。
- 19.8 的版本 bump 提交 `f9e69715f` 不在当前祖先链中；19.8 内容是否已被后续同步吸收，必须按文件和提交逐项确认，不能按版本号推断。

## 已确认的官方范围

19.8 到 19.9-rc1 的共同基线段为 564 条；从该分叉点分别审计 beta 线的 565 条和发布线的 808 条。现有两份同步台账已经覆盖其中一部分：新增提交台账 89 条，旧台账复核 235 条；但台账状态包含 `adapted-local`、`covered-equivalent`、`deferred-*` 等分类，不能直接等价为“20.0 已合入”。

已确认进入当前代码或有本地等价实现的重点范围包括：snapshot delta 容量与失败传播、vanilla 0.6 暂停快照、playermapping 与旧客户端限制、任意客户端重连、old laser/GameInfoEx、输入时序、低刷新率渲染调度、macOS/iOS 适配、EGL headless/map_render、teehistorian role names、编辑器 modifier 快捷键及构建链更新。

## 当前未决项

1. 逐项生成 `19.9-rc1..20.0` 官方提交清单，并与新增台账、旧台账和当前文件差异做交叉匹配。
2. 对 `covered-equivalent` 与 `adapted-local` 条目补充实际代码位置和行为证据，区分真正功能等价与仅有相似结构。
3. 对 `deferred-platform`、`deferred-policy`、`deferred-protocol-batch` 和版本号条目单独列出，不混入已合入统计。
4. 审计完成前不把版本号从 19.9 改为 20.0。

## 第 12 轮独立审计结论

官方 `19.9-rc1..20.0` 的 808 条提交不能用官方 SHA 是否直接出现在当前祖先链判断：QmClient 使用了本地分支、合并包装和适配提交，官方 PR 提交通常对应另一个父提交或不同提交说明。按提交主题、文件差异和当前调用链复核后，结论分为以下几类。

### 19.8 到 19.9-rc1 的专项核验

- snapshot Rust 化：官方 `a1e9d2b3c8` 在当前分支不是同一 SHA，但本地 `fe08e537f` 已引入 `src/engine/shared/snapshot/builder.rs`、`delta.rs` 和 bridge；后续 `99f85acb7` 处理 sixup ID 重复，不能标成缺失或原样 cherry-pick。
- 0.7 snapshot 分流：官方 `77d5448063` 的语义在当前 `CServer` 中由 `m_pSnapshotDelta` 与 `m_pSnapshotDeltaSixup` 两条 delta 状态承担，`server.cpp:253-264` 和 `server.cpp:1160-1162` 可直接核对，属于本地适配。
- demo/暂停状态：当前有 `CGameClient::IsWorldPaused`、`IsDemoPlaybackPaused`、`GetAnimationPlaybackSpeed`，并在 `gameclient.cpp:3825-3836` 处理当前 tick 的暂停状态；这覆盖了官方暂停语义，但不代表所有 demo UI 行为已完成运行时验收。
- map/editor 接口迁移：当前 `IMap`、`render_map`、多地图 editor 状态和 `CMapView` 分拆均已存在；这些提交不能仅按官方文件名判断为缺失，但仍需保留 QmClient 本地 ownership 差异。
- snapshot/delta 容量与失败传播：当前 `CSnapshotDeltaBuffer`、server/demo 的失败返回处理和 `snapshot_test` 已覆盖；这属于本地 Rust 架构下的等价修复，不是官方旧 C++ API 的原样合入。

进一步对当前 `HEAD` 的提交和调用点核对后，上述项目中已有本地对应，不能再列为缺失：`9226cb6a69` 对应 `ee92899ad`（客户端按 0.6/0.7 选择两套 demo recorder）；`b03ccff45e` 对应 `92f5b19fd`；`3041cc262c` 对应 `945b53f59`；`6cc1dd44ef` 对应 `d2389d362`；`4299da8fb8` 对应 `3c2d69927`；`9fc6144725` 对应 `bb29a59a6`；`32fef046e0` 对应 `a44f84792`；`737d8e1d0c` 对应 `9b8ef4765`/`a98fdc1a7`。这些归类为本地适配或功能等价，仍保留对应平台/运行时验证缺口。

当前仍需继续确认的 19.8 高风险项目，主要集中在官方 snapshot Rust 迁移后的接口重构、demo delta 4 字节修复、暂停语义的完整 UI 行为、Emscripten 打包细节以及若干纯编辑器拆分提交；它们不能因为当前存在同名函数就自动计为原样合入。

### 已确认有本地实现或等价覆盖

- 输入前移：官方 `3cbe5a0e58df`，本地 `b665e5ea6`；`OnUpdate` 已位于网络泵之后、输入采集与预测余量更新之前。
- 任意客户端重连与 playermapping/vanilla 0.6：官方 `ec4708fbd`、`4319e202f`、`f52348ddb`、`e20c0e3d` 等，已由 `dfd0ef13e`、`ff802f4cf`、`27f4bcf02` 等本地提交落地；代码审计覆盖槽位、旧客户端限制、暂停快照和重连状态。
- snapshot delta 容量/失败传播、地图 SHA256、old laser/GameInfoEx、控制台 victim 槽位限制、DSCP EF、编辑器字体输入器绑定：已有对应本地实现和测试/构建证据。
- MySQL TLS、0.7 地图下载校验、snapshot item 对齐、EGL 无窗口地图渲染、teehistorian role names、macOS/iOS 的部分构建适配：当前源码中存在对应实现；其中平台行为仍不等价于真机验收。

### 明确不能宣称为“官方 20.0 已合入”

- 版本 bump：官方 `f82770664` 将 `DDNET_VERSION_NUMBER`/`GAME_RELEASE_VERSION_INTERNAL` 改为 `20000`/`20.0`；当前仍为 `19090`/`19.9`。这是发布策略决定项，暂不修改。
- 冻结拾取雪花：官方 `6a312c350`/候选 `acfefe91e` 需要协议、玩法和资源同步；当前仍无 `POWERUP_FREEZE`、`VERSION_DDNET_PICKUP_FREEZE` 和雪花资源，不能按“已有冻结语义”计为合入。
- 渲染调度重构：官方 `d1de8dfd1`/`484b513b1` 的 `NextUpdateTime`/`NextRenderTime` 网格与当前 `LastRenderTime`/`AdditionalTime` 结构不同；本地只有行为适配和 Qm 自有限速，不能称原样合入。
- EGL/独立 map renderer：官方提交的目标文件和工具链与本地不同；当前 `85bd6cb6f` 是 QmClient 对无窗口接口的适配，不是官方 `backend_egl.cpp`、`FindEGL.cmake` 和完整工具集合的原样合入。
- 构建/平台策略、翻译生成、CI 和纯重构提交：按 QmClient 的本地生成链、Apple/Windows 构建边界和不引入无效迁移测试的要求，不能仅凭源码相似或测试通过计为官方提交已合入。

### 仍需单独源码/运行时核验的官方提交

下列官方提交在当前台账中没有可直接复用的明确证据，不能自动标成已合入：`f5718e7ac`（连接阶段地址限制）、`ee2e804c4`（Vulkan OOM device-lost）、`1b42e3760`（拒绝超大未压缩包）、`9a19cc7c9`（非法 savegame）、`3a2dd0a66`（render_map 崩溃）、`16f9db668`（freeze bars 崩溃）、`4af8164f2`（动态 antiping 预测）、`a5d48b817`（连接/换图崩溃集合）、`86fed1482`（macOS semaphore 泄漏）以及官方 20.0 的 iOS/Emscripten/CI 工作流提交。它们需要逐项对照 patch-id、调用链和目标平台构建，不能用“当前有相似代码”替代。

## 审计边界

本轮没有修改协议、版本号或平台发布策略，也没有把迁移型源码字符串测试重新加回去。Windows、WSL2 EGL、Rust、C++ 和 default gate 的既有证据继续有效；macOS 真机、双客户端重连、0.6/0.7 兼容、KCP/DSCP 链路和 Apple 发布签名仍属于运行时/平台验证缺口。
