## 0. 当前结论

原报告的主要判断已经过时，尤其是把旧的 `19.9-rc1..master` 增量和 416 个提交继续当作当前同步口径。

- QmClient **仍使用 DDNet 19.9 版本标识**：`src/game/version.h` 中的 `GAME_RELEASE_VERSION_INTERNAL` 仍为 `19.9`。
- QmClient **已经部分同步 20.0 开发内容**，但不是完整的官方 20.0 快照。可验证的同步记录包括：
  - `aec0a1370`（2026-08-05）：同步 DDNet 19.9 与开发者认证；
  - `5e022ee92`、`bd1a55607`、`c519155c9`（2026-08-21）：基础库/服务端、客户端、编辑器与地图工具同步批次；
  - `8de34fd77`（2026-08-22）：信封编辑器组件化与 per-map 状态隔离。
- 历史上曾有 `8ec0f6700`（2026-04-19）把 beta 版本号 bump 到 20.0，但当前 `src/game/version.h` 已回到 19.9，因此不能据此声称当前版本为 20.0。
- 官方已经发布 `20.0` tag：`a5a61806e434`（2026-08-21 16:12:33 +0200）。
- 因此，“20.0 仍在开发”需要拆开理解：`20.0` 已在 2026-08-21 打 tag，但官方 `master` 仍在继续开发（其中已有 20.1 开发版本号调整）。
- 当前活动校对基准已刷新为 `ddnet-official/master` `b427813d2dbb`（2026-08-31），位于 `20.0` tag 之后 **229 个提交**；`944ac7b28ef1` 仅是早期报告基准。
- 因为 QmClient 采用同步提交/cherry-pick 和自有改动，`20.0` tag 不是 `dyl_dev` 的祖先。不能用 merge-base 或版本号单独判断“是否已同步完整”。
- iOS P3A/P3B 已按当前 QmClient 所有权在工作树实现，仍未提交：iOS SDL/OpenGL ES app bundle、xcframework/Rust target、平台入口、文件系统/生命周期和 EPIPE 后 UDP socket 重建均已有源码和构建/测试证据。P3C（simulator 安装/启动与真机）仍未完成。

## 3. QmClient 当前基线与合并建议

### 已进入本地分支的部分

- 19.9 同步及其后的自有 QmClient 改动已经进入 `dyl_dev`。
- 128 player、IHttpRequest 生命周期、多地图 editor tabs 等专项已有本地实现或后续修复；`docs/superpowers/plans/2026-08-23-upstream-206-followup.md` 记录了这些范围和剩余运行时缺口。
- QmClient 在校对时的工作树还包含近期 Metal、统计和预测改动；上游同步时必须保留这些本地行为，不应按旧报告的“纯上游分支”假设处理。

### 暂不能声称已完成的部分

- 本地版本号还不是 20.0，不能称为“已同步到官方 20.0”。
- 当前没有**官方 hash 原样进入、且与 `b427813d2dbb` 基线对应**的逐提交覆盖清单；版本化台账记录的是本地适配、等价覆盖和延期策略。`tmp/` 下的历史审计和标题比对产物不能作为权威输入。
- iOS P3C 尚无 simulator runtime、AppIcon 编译、app 安装/启动、GLES、触控、联网、后台恢复、截图、Files export、退出、真机或 CI 证据；这些不能由 bundle build 代替。
- Emscripten、0.6 兼容、官方 editor tabs/UI 重构和 Vulkan 改动仍需要逐项判断，不能从主题名称直接合入。

### 推荐顺序

1. 先以 `20.0..ddnet-official/master` 的 229 个提交作为当前增量入口，不再使用旧的 416 清单。
2. 先筛选安全性、崩溃、OOB/UB、构建修复；每个提交核对 QmClient 是否已有等价修复。
3. 先完成 iOS P3C：安装 simulator runtime 后重开默认 AppIcon build、安装/启动 simulator app，再做已签名 arm64 真机 smoke；iOS 原生 Metal 另建专项计划，不阻塞 SDL/OpenGL ES bring-up。
4. 每批同步后按 `qmclient-verification-gate` 串行执行适用的构建、测试和 gate；未做真实运行时或真机验证的内容必须保留 gap。
