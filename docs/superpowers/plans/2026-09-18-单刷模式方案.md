# 单刷模式（开局分队 + 起点前一键恢复）方案

日期：2026-09-18　状态：设计稿（未实现）

## 1. 目标与使用场景

双开刷图（本体 + 分身）时，两者同队会互相干扰（挡路、互相锤、分数混在一起）。本功能提供：

1. **开局分队**：进入地图/新局时，让本体与分身进入**不同的 team**，各自独立单刷；
2. **起点前一键恢复**：计时开始前（未过起点线）一键把两者恢复到进入本局前的 team，再开始正式跑图；
3. 提供显式的"单刷模式"开关与键位，避免依赖手输 `/team`。

注意：这里的"分队"与客户端/服务端的 **solo 标志（`CHARACTERFLAG_SOLO`）是两个独立概念**。本方案只操作 **team**，不改 `m_Solo`；是否叠加 solo 由用户自行决定（可后续扩展）。

## 2. 行为定义（对外语义）

| 状态 | 本体 | 分身 | 说明 |
| --- | --- | --- | --- |
| 单刷模式关闭 | 保持原样 | 保持原样 | 不插手任何 team |
| 单刷模式开启 + 新局 | 决定的目标 team | 另一个 team | 只在"计时开始前"执行 |
| 起点线之前按恢复键 | 恢复到进入前 team | 恢复到进入前 team | 一键，幂等，可重复按 |
| 计时已开始 | 不再自动分队 | 不再自动分队 | 避免污染成绩/排行榜 |

关键约束：**所有自动动作只允许发生在"计时开始前"**；一旦过了起点线，本功能必须完全静默，避免影响比赛成绩。

## 3. 触发与判定

### 3.1 "新局"的判定

候选信号（按可靠性排序，需实机验证其一）：

1. `CGameClient::OnNewSnapshot()` 中 race 状态从"未开始/Reset"变为"运行中"的翻转；
2. `m_Snap.m_pGameInfoObj->m_RaceStartTick` / 本地玩家 `m_StartTime` 未设置（DDNet 里未开始计时时的取值需要确认）；
3. 地图切换事件（`OnStateChange` ONLINE→LOADING→ONLINE 或 `m_GameInfo.m_MapName` 变化）。

建议实现为纯函数输入，便于测试：

```cpp
struct SQmSoloStartSignals
{
    uint64_t m_RunEpoch;              // 地图/重置后递增；不能只靠 RaceActive 的电平
    bool m_RaceActive;                // 本局已开始计时
    bool m_LocalPlayable;             // 本体在游戏队伍且可发送命令
    bool m_DummyConnected;
    int  m_LocalTeam;                 // vanilla m_aClients[].m_Team，/team 修改的是这一层
    int  m_DummyTeam;
    int  m_EntryLocalTeam;            // 首次分队前捕获；无快照时为 TEAM_SPECTATORS
    int  m_EntryDummyTeam;
    bool m_EntryTeamsCaptured;
    bool m_LocalTeamChangePending;
    bool m_DummyTeamChangePending;
    bool m_RestoreRequested;          // 仅在 RaceActive=false 时消费
};
```

实现必须把 `m_RunEpoch` 与执行状态一起保存：`Idle -> Captured -> SplitPending -> Split -> Restored/Aborted`。进入新地图、服务器重置、断线或本体/分身重新连接时开始新的 epoch；用户在分队期间手动改 team 时放弃该连接的自动恢复责任。`m_EntryLocalTeam/m_EntryDummyTeam` 必须在第一条 `/team` 发出前原子捕获，不能用当前 team 推导恢复目标。

### 3.2 "起点前"的判定

至少满足其一即视为可操作窗口：

- 本局计时尚未开始（`RaceActive == false`）；
- 可选：本地玩家位置的 x 坐标在地图起点之前（需要 GPS/起点标记数据，成本高，建议 P2 再做）。

### 3.3 一键恢复的可用性

- 恢复键也必须满足"计时未开始"；过线后自动动作和显式 `/team` 均不发送，功能保持静默；
- 若服务器拒绝（见 §6），要给出明确提示，而不是静默重试。

## 4. 实现分层（遵循本仓库惯例）

| 层 | 位置 | 内容 |
| --- | --- | --- |
| 配置 | `src/engine/shared/config_variables_qmclient.h` | `qm_solo_start_enable`(0/1)、`qm_solo_start_key`(键位)、`qm_solo_start_local_team`/`_dummy_team`（默认 1/2）、`qm_solo_start_auto_restore`(计时开始前是否在关闭模式或恢复请求时自动恢复) |
| 纯逻辑 | `src/game/client/components/qmclient/modes.{h,cpp}` | `QmResolveSoloStartPlan(Signals, Config) -> SQmSoloStartPlan{ NeedSplit, NeedRestore, LocalTeam, DummyTeam, RestoreLocalTeam, RestoreDummyTeam }`；plan 只在 `RaceActive=false` 且 epoch 有效时产生动作 |
| 执行 | `src/game/client/components/tclient/tclient.cpp` | 在 tick 中调用 `GameClient()->m_Chat.SendChatOnConn(IClient::CONN_MAIN/CONN_DUMMY, 0, "/team <n>")`；维护每个连接的目标、重试次数、deadline、失败原因和 epoch |
| 失败检测 | 同上 | 监听服务器系统聊天（可复用 `axiom_auto_login` 的 `ClientId < 0` 消息处理模式）或比对 `m_aClients[].m_Team` 是否在若干 tick 内生效，超时则提示并停止 |
| UI | `src/game/client/components/qmclient/menus_qmclient.cpp` | 功能卡片新增「单刷模式」区块：总开关、恢复键位、本体/分身 team 选择、当前状态显示（已分队 / 已恢复 / 被服务器拒绝） |
| 命令 | 控制台 | `qm_solo_start split` / `qm_solo_start restore`（可绑键；restore 在计时开始后无效） |
| 文案 | i18n | 新增文案走 `translations/i18n/qmclient.toml` + `generate_all.py`，12 语言齐全后方可提交 |

数据流：

```
tick → 收集 Signals(race/team/dummy) → QmResolveSoloStartPlan
     → 需要动作且未在途 → 发 /team 命令（本体 + 分身）
     → 观察生效（m_Team 变化 / 服务器拒绝消息）→ 更新状态 → UI 显示
```

## 5. 交互与边界

- **与快速练习（fast_practice）的关系**：`tclient/fast_practice.cpp` 已有 dummy 输入注入与 `/practice`、`/solo` 相关命令；本功能只做 team，不复用它的输入通道，也不发送 `/solo`。两者同时启用时，本功能只在自己的 epoch 和 `RaceActive` 门禁内工作。
- **与 Gores 模式**：Gores 的分身锤联动、自动启用（`qm_gores_auto_enable`）都会改分身状态；单刷模式开启时应避免同时自动开 `qm_gores`（建议：单刷模式下不触发 Gores 自动启用，或在 UI 里提示冲突）。
- **分身未连接**：分身不在线时只处理本体，并在 UI 显示"分身未连接"。
- **旁观/观战**：本地处于旁观时不执行任何 team 动作（无 tee 可分队）。
- **幂等**：同一目标 team 不重复发送；按键恢复同样幂等。

## 6. 风险与需要实机确认的点

| 风险 | 说明 | 处理 |
| --- | --- | --- |
| `/team` 被服务器限制 | `sv_team_lock`、队伍人数上限、race 服可能禁止换队 | 检测服务器拒绝消息 → 明确提示 + 停止重试 |
| 分队影响成绩 | 不同服务器对 vanilla team、DDRace team、race 计分和排行榜的关系可能不同，不能把“不会进主榜”当成已证实事实 | 只允许在计时开始前执行；UI 明示“仅单刷用”；P1 实机确认并记录服务器行为 |
| 起点线前判定 | 仅用"计时未开始"可能覆盖不到 reset 之后的窗口 | P1 先用计时状态，P2 再考虑起点坐标 |
| 与 dummy 自动连接（Axiom）叠加 | `axiom_auto_login` 会在进服时自动连分身并发 `/login` | 分队命令在分身连接完成后才发（等待 `m_DummyConnected` + 登录完成标志，或固定延迟重试上限） |
| 反复发送 | 服务器未生效时反复刷屏 | 去抖 + 最多 N 次 + 超时停止（同 Axiom 登录的做法） |

## 7. 分期实施

- **P0（最小可用）**：控制台命令 + 键位，手动一键"分队 / 恢复"，捕获进入前 team，无 UI、无自动开局分队。
- **P1**：开局自动分队（计时未开始时触发）+ 失败检测提示 + 状态显示。
- **P2**：UI 卡片（开关/team 选择/状态）、i18n 12 语言、`qm_solo_start_auto_restore` 等选项、起点坐标判定。

## 8. 验收标准与测试

纯函数单测（`src/test/qm_modes_test.cpp` 或新文件）：

- `QmResolveSoloStartPlan`：计时中 `NeedSplit=false` 且 `NeedRestore=false`；新 epoch 首次调用先捕获 entry team，再要求分队；同 epoch 同目标不重复要求；分身离线时只产生本体动作；恢复 plan 使用捕获的 entry team。
- `QmShouldSendSoloStartCommand`：去抖/上限/超时后不再发送，且返回"已放弃"状态；epoch 变化清空旧 pending，用户手动改 team 后不覆盖用户值，本体/分身分别成功和分别超时。

手工验收：

1. 开启单刷模式 → 进图（计时前）→ 本体/分身分别在不同 team，UI 显示"已分队"；
2. 按恢复键 → 两者回到进入前 team，UI 显示"已恢复"；
3. 过起点线后再按 → 无 `/team` 发送、无状态污染，功能保持静默；
4. 在禁止换队的服务器 → 出现明确失败提示，且不再重复刷屏。
