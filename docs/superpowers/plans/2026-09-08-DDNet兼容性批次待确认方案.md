## A：快照 delta 容量与失败处理

官方 `be3e5e6a3` 同时修改客户端解压、服务端发送、demo 录制与共享 delta 接口。官方用两倍 CSnapshot::MAX_SIZE 的对齐缓冲区；压缩失败或包数过多时跳过发送，demo chunk 写入未成功时不更新录制基准。

本地使用 Rust `src/engine/shared/snapshot/delta.rs`，不是该提交的 C++ CreateDelta 实现。Rust write_to_ints 失败返回 -1；server.cpp 和 demo.cpp 仍用 if(DeltaSize) 进入后续处理。demo Write 只排除大于64KiB的长度，负长度会到达 mem_copy。此为源码上可见的失败传播缺口，尚未构造有效大快照触发回归用例，不宣称已复现崩溃。

适配范围：

1. 保留 Rust 编解码器及当前 snapshot/网络格式；核对两个最大合法快照产生 delta 的容量上界，统一客户端解压、服务端和 demo 的对齐缓冲区容量。
2. 明确区分 CreateDelta 的负值失败、零变化和正值成功；负值不得进入压缩或 Write，Write 也拒绝负长度。
3. 服务端检查压缩失败和分片数量，保留本地 KCP 队列退避逻辑。
4. Write 返回是否接受并写出 chunk，RecordSnapshot 仅在成功路径推进 delta 基准；保留本地显式 Keyframe 重载和剪辑调用语义。是否检查底层短写需另读 IO 契约，不能将官方布尔结果解释成持久化保证。

验证：先构造不足容量的 Rust delta 返回值用例及接近上界的合法快照；覆盖录制失败后下一条 delta 的基准、显式关键帧剪辑、普通 demo 回放、0.6/0.7客户端与服务端互通。运行 C++/Rust 全量以及客户端/服务端构建。该批触及共享快照与回放错误语义，需明确批准。

## B：输入更新前移

官方 `178da1ead` 将 editor/gameclient OnUpdate 从 CClient::Update 后部移至 PumpNetwork 后、输入快照采集前。本地仍在后部执行，且 PumpNetwork 后先更新预测余量。当前不是源码等价覆盖。

适配前先画出本地输入事件、OnUpdate、输入采样/发送和预测余量更新的实际顺序；确定 OnUpdate 在本地预测余量更新前后的放置位置。保留主副角色、录制回放及编辑器路径。验收需记录正常与低帧率下的事件到输入发送顺序，以及主副角色切换、UI捕获输入和demo播放行为。预期会改变输入处理时序，独立批准后实施。

## C：地图兼容性匹配增加 SHA256

官方 `a34ebba73` 给 CMapDescription 相等判断增加 SHA256。当前仅比名称及大小；Binary 地图兼容项启用 BUG_GRENADE_DOUBLEEXPLOSION，服务端 projectile.cpp 消费该标志。

适配仅增加摘要比较和对应测试：正确三元组仍匹配；名称、大小或摘要任何一项不同均不匹配。本地加载前用零大小/零摘要初始化，加载成功后取真实地图 Size/Sha256；该路径已核对。行为变化是同名同大小但内容不同的地图不再继承此历史榴弹兼容行为。客户端和服务端应同步，需明确批准地图行为变化。

## D：old laser 状态经 GameInfoEx 同步

官方 `79184e826` 在 `GameInfoFlags2` 末尾新增 `OLD_LASER`，服务端在 `sv_old_laser` 开启时置位，客户端读取到 `CGameInfo::m_OldLaser` 并写入预测世界配置，`prediction/entities/laser.cpp` 的四处判断从 `g_Config.m_SvOldLaser` 改为 `GameWorld()->m_WorldConfig.m_OldLaser`。

本地现状：`datasrc/network.py` 的 `GameInfoFlags2` 没有该位，`gameclient.h`/`prediction/gameworld.h` 没有 `m_OldLaser`；`laser.cpp:39、46、56、67` 与 `qmclient/weapon_trajectory.cpp:280` 仍用客户端配置。结果是服务器开启 `sv_old_laser` 而客户端未开启时，本地预测与服务器行为不一致（官方 issue 中的激光不可见/命中差异）。

适配范围：新增一个 gameinfo 标志位（追加到末尾，旧客户端忽略未知位），客户端读取后写入 `WorldConfig`，预测激光与本地轨迹预测都改用该值；`weapon_trajectory.cpp` 属于 QmClient 自有代码，需单独确认是否同步改为服务器值。该改动触及协议字段与预测行为，需明确批准；验收要覆盖 `sv_old_laser` 开关组合下的激光命中与自伤表现，并确认对未发送该标志的旧服务器回退为客户端配置。

## E：vanilla 0.6 客户端的暂停快照

官方 `60d9886cf` 在 `CPlayer::FakeSnap` 末尾为 `VERSION_VANILLA` 且处于 `PAUSE_PAUSED` 的客户端补发 `PlayerInfo`（`m_Local = 1`、`TEAM_SPECTATORS`）与 `SpectatorInfo`，让原版 0.6 客户端也能进入暂停视图。

本地 `player.cpp:486-536` 的 `FakeSnap` 没有这段逻辑，且结构已按玩家映射改写（提前返回 128 人客户端与 0.7 客户端、用 `SeeOthersId` 发送伪对象）。适配需要确认：追加位置、与玩家映射伪对象的交互、`m_SpectatorId` 的 `Translate` 回退，以及原版客户端实机验收（当前环境无原版 0.6 客户端）。该改动改变旧客户端的快照内容，需明确批准。

## F：控制台按 Slot 取 victim 与 id 命令的旧客户端限制

官方 `f586be3e0` 把控制台的单个 victim 改成按参数槽位保存（`IResult::GetVictim(unsigned Slot)`、`AddVictim`/`SetVictim(Slot, Id)`、`m_vVictims`），给 `ICommandInfo` 增加 `TakesClientId()`（参数串含 `v` 即为真），并在 `IServer` 增加 `ClientUsesRealClientIds()`：`CanClientUseCommand` 对“含 id 参数”的命令，在调用者看不到真实客户端 id（旧客户端经 id 映射）时直接拒绝；同时把 `set_team`、`tele` 等命令的参数类型从 `i[id]` 改成 `v[id]`，并删除 `set_team_all`。

本地现状：`console.h:86` 的 `GetVictim()` 无槽位参数，`ICommandInfo` 没有 `TakesClientId`，`console.rs:323` 与 `rust-bridge/cpp/console.cpp:127` 也是旧签名；`server.h` 没有 `ClientUsesRealClientIds`，`gamecontext.cpp:3922` 的 `set_team` 仍用 `i[id]`、`:3953` 的 `tele` 仍是 `?i[id] ?i[id]`。风险是经 id 映射的旧客户端上，管理员按看到的 id 执行命令会作用到另一个真实客户端。

适配范围：控制台多 victim 重构（含 `CResult` 拷贝构造、命令分发处的 fan-out）、Rust FFI（`console.rs` 与 `src/rust-bridge/cpp/console.cpp` 需同步，该文件是签入的生成产物）、`server.h` 的新查询、`CanClientUseCommand` 拒绝逻辑、`set_team`/`tele`/`kill_pl`/`muteid` 等命令的参数类型与回调取值。该改动会改变服务器命令行为（尤其 `/tele`、`/set_team`），需明确批准并覆盖：旧客户端管理员执行 id 命令被拒绝、0.7/128 人客户端正常、`all`/`me` 特殊 victim 展开、teehistorian 命令记录仍一致。

## G：任意客户端重连结构（7131ad28b、b946fa9a2）

官方 `7131ad28b` 把重连回调改成 `NETFUNC_CLIENTREJOIN(ClientId, pUser, Sixup, VanillaAuth)`，在 `CNetServer::AcceptConnection` 里按 `Reconnect/VanillaAuth` 分流到 `m_pfnClientRejoin` / `m_pfnNewClientNoAuth` / `m_pfnNewClient`，并用 `CServer::CClient::m_Rejoining` 标记“正在重连、暂不改状态”的槽位；`b946fa9a2` 再补上 `Reset()` 里清 `m_Rejoining`，避免换图后残留。

本地现状：`network.h:165` 的 `NETFUNC_CLIENTREJOIN` 仍是 `(ClientId, pUser)`，`network_server.cpp:643` 在 `OnConnCtrlMsg` 里直接调用，`CServer::ClientRejoinCallback`（`server.cpp:1195`）是独立函数，`CClient` 没有 `m_Rejoining`，`DoSnapshot`、`ProcessClientPacket` 等处也没有该判断。

适配范围：`network.h` 回调签名、`network_server.cpp` 的连接接受与重连分流、`server.h/server.cpp` 的回调实现与 `m_Rejoining` 状态（含 `Reset()`、`DoSnapshot`、`ProcessClientPacket` 的过滤）、`gamecontext` 的 `OnClientRejoin` 路径。风险是改变连接建立与重连语义，需覆盖：正常连接、同 IP 断线重连、换图时重连、0.7/0.6 客户端、KCP 通道重连、与本地玩家映射的交互。建议单独批次实施，先用 `gameworld_test.cpp`/`network_test.cpp` 补可测路径，再做双客户端实机重连验收。
