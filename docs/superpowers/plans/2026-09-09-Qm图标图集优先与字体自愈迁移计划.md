# 目标

让 QmClient 的图标以 SVG 生成的图集（MSDF 优先、alpha 兜底）为主路径，TTF 字形只作失败回退；
同时让用户零手工配置即可获得随包 Phosphor 字体，并修掉“用户目录旧字体索引导致满屏方框”的根因。

# 已完成

## 1. 字体自动可用（已验收）

- `data/fonts/Phosphor-{Regular,Bold}.ttf` 移到 `data/qmclient/fonts/`（QmClient 专属字体目录），
  `LoadCustomFonts()` 会自动加载该目录，不再依赖共享的 `fonts/index.json`。
- `LoadFonts()` 新增图标面自愈：按 `FontIcons::FONT_ICON_ALL`（87 个码位）做覆盖率校验，
  缺失时回退到随包 `Phosphor`/`Phosphor-Bold` 并告警。
- `InstallBundledIconFonts()`：首次启动把两份 TTF 复制到 `$USERDIR/qmclient/fonts`。
- `textrender.h` 新增 `FontIcons::FONT_ICON_ALL`；`data/fonts/index.json` 不再列这两份字体；
  `CMakeLists.txt` 数据清单改为 `qmclient/fonts/Phosphor-*.ttf`。
- 共享的 `%APPDATA%\DDNet\fonts\index.json` 已恢复原状（DDNet 原版/BestClient 不受影响），
  QmClient 侧靠上面的自愈逻辑工作。

验收证据（开发实例 stdout，共享索引为原版 Font Awesome 状态）：

```text
I textrender: Installed bundled icon font 'qmclient/fonts/Phosphor-Regular.ttf'
I textrender: Installed bundled icon font 'qmclient/fonts/Phosphor-Bold.ttf'
W textrender: Font index has no 'icon bold' string, using the regular icon face for bold icons
W textrender: The configured icon font misses 74 of 87 FONT_ICON_ glyphs, using the bundled 'Phosphor' instead
I textrender: Icon font face: 'Phosphor'
```

## 2. 图集全覆盖（已生成产物）

- 87 个 `FONT_ICON_*` 全部有对应图集格子：`EQmIcon` 从 16 个扩到 94 个（新增 78 个），
  `CQmIconManager::IconName` 改成单张 `{EQmIcon, name}` 表，`IconFromName` 复用该表。
- `datasrc/qm_icons/phosphor_{thin,regular,bold,fill}/` 从 17 个 SVG 扩到 95 个（新增 78 格，
  其中 `backward-step`/`forward-step` 与 `skip-back`/`skip-forward` 内容相同以避免一格两枚举）。
- 产物全部重建：`data/qmclient/icons/qm_icons_{thin,regular,bold,fill}_{1x,2x,4x,msdf}.{png,json}`，
  每个清单 95 格、覆盖全部 94 个枚举名（`tmp/icon-diff/verify_manifest.py` 校验）。
- MSDF 用本机自建 msdfgen 生成（`tmp/msdfgen-build/msdfgen.exe`，`MSDFGEN_USE_VCPKG=OFF` +
  `ddnet-libs` 的 freetype/libpng + 本地 tinyxml2）；`plus` 单元格与既有产物逐像素一致（最大通道差 0）。
- MSDF 后端覆盖：Vulkan / OpenGL 3.3+ / OpenGLES 3 / Metal 均已实现 MSDF 采样；
  仅 legacy OpenGL 1.x 与未覆写 `HasTexturedMsdf()` 的后端回退到 alpha 图集。

## 3. 调用点迁移（已完成）

新增原语（`src/game/client/ui.h|ui.cpp`、`components/menus.h|menus.cpp`、`game/editor/editor.h|editor_ui.cpp`）：

```cpp
bool CUi::DrawQmIcon(const CUIRect &Rect, EQmIcon Icon, const char *pFallbackIcon, const ColorRGBA &Color);
CLabelResult CUi::DoLabel_QmIcon(const CUIRect *pRect, EQmIcon Icon, const char *pFallbackIcon, float Size, int Align, const SLabelProps & = {});
int CUi::DoButton_QmIcon(CButtonContainer *pBtn, EQmIcon Icon, const char *pFallbackIcon, int Checked, const CUIRect *pRect, unsigned Flags, int Corners, bool Enabled, std::optional<ColorRGBA>);

int CMenus::DoButton_MenuTab_QmIcon(CButtonContainer *pBtn, EQmIcon Icon, const char *pFallbackIcon, int Checked, const CUIRect *pRect, int Corners, CAnimator *, ColorRGBA, ColorRGBA, ColorRGBA, float, IGraphics::CTextureHandle, CUIElement *, float);
int CMenus::DoMenuTabV2_QmIcon(CButtonContainer *pBtn, EQmIcon Icon, const char *pFallbackIcon, bool Active, const CUIRect *pRect, int Corners, ColorRGBA, ColorRGBA, ColorRGBA, IGraphics::CTextureHandle, CUIElement *, float);
```

统一语义：图集未就绪或该图标缺失时，用 `pFallbackIcon`（`FontIcons::FONT_ICON_*`）走 TTF 字形。
`gameclient.cpp` 在 `m_QmIconManager.Init(...)` 之后调用 `m_UI.SetQmIconManager(&m_QmIconManager)`。
原有 `*Internal` 实现保留为唯一实现体，旧签名（纯字形）与新签名都转发到它，避免两份绘制逻辑漂移。

迁移规模：约 170 处调用点，覆盖
`ui.cpp`、`menus*.cpp`、`hud.cpp`、`scoreboard.cpp`、`chat.cpp`、`spectator.cpp`、
`qmclient/*`（含 `voice/voice_core.cpp`、`menus_qmclient.cpp`）、`tclient/menus_tclient.cpp`、
`editor*.cpp`、`file_browser.cpp`、`QmUi/SettingsCard.cpp`、`key_binder.cpp`。

**有意保留字形路径**（不迁移，附原因）：

| 位置 | 原因 |
| --- | --- |
| `hud.cpp` `RenderTextEye`（2 处） | 眼睛图标按注视方向做路径形变，需要字形轮廓 |
| `nameplates.cpp` `CreateOrAppendTextContainer`（2 处） | 名字板文本流内联图标，与文字基线/字距绑定 |
| `scoreboard.cpp` `TextEx(FONT_ICON_COMMENT_SLASH)` | 与后面的文字同段拼接，属文本流 |
| `menus_browser.cpp` 复合刷新/连接按钮标题（3 处） | 标题由多段文本拼成，非独立图标位 |
| `menus_demo.cpp` 排序表头标题 | 同上，表头标题文本流 |

# 运行时验收（全新构建目录）

共享的 `cmake-build-release` 目录里构建出的 `DDNet.exe` 启动约 1–6 秒后以 `0xC0000005` 退出，
崩溃点随构建漂移（符号化为 `CSkins::OnConsoleInit`、`CSounds::OnInit` 等组件初始化点），
而同一份源码在**全新构建目录**（`cmake-build-iconcheck`，`-DCMAKE_BUILD_TYPE=Release`）里构建后正常运行：

- 窗口 1.3 秒出现，主菜单稳定运行 30 秒以上，HTTP/皮肤/识别请求全部完成；
- 结论：崩溃来自共享构建目录里的陈旧/不一致产物（此前该目录出现过 `failed recompaction: Permission denied`
  与残留 ninja/cl 进程），不是源码问题。建议在 `cmake-build-release` 里做一次干净重建恢复。

图标运行时证据（`qm_perf_debug 1` + `qm_perf_logfile 1`，日志在
`$USERDIR/dumps/QmClient_Perf/qm_perf_*.log`）：

```json
{"event":"icon_frame","alpha_draws":0,"msdf_draws":28,"reload_attempts":1,"reload_successes":1,
 "msdf_probe_attempts":1,"msdf_probe_successes":1,"atlas_swaps":1,
 "texture_load_successes":1,"texture_load_failures":0}
{"event":"icon_frame","alpha_draws":0,"msdf_draws":51,"msdf_manager_call_run_max":51,...}
```

即：图集纹理加载成功、走 MSDF 绘制（`msdf_draws` 增长、`alpha_draws` 为 0、无加载失败），
与字体日志中的 `Icon font face: 'Phosphor'` 共同证明图集主路径与字形回退都健康。

命令行传参注意：本仓库 `CConsole::ParseArguments` 不剥离 `+` 前缀，
正确写法是单引号包住整条命令，如 `DDNet.exe "qm_perf_debug 1" "logfile <绝对路径>"`。
