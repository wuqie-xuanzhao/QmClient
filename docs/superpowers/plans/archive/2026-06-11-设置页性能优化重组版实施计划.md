# CMenus 级设置页菜单文本池完整重构 Implementation Plan

> **2026-06-13 收口更新：** 本计划原版中的 visible 阶段文本预构建设计已被更新后的 `docs/superpowers/specs/2026-06-11-设置页性能优化总纲-重组版.html` 覆盖。当前实现以 spec 为准：`PrewarmVisibleSettingsResources()` 只保留资源预热，稳定文本池只能在不可见阶段预算构建；target settings / ingame Esc 窗口必须提供 `settings_text_usage` 利用率口径，缺失 usage、miss、stale 或 target 前 remaining 都会让 `targetSettings` 标为“不足以验收”。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立 `CMenus` 级通用菜单文本池，先只在 settings 作用域启用，让 `settings:tclient`、`settings:qmclient` 和 `ingame_esc_open` 目标窗口中的稳定文本只复用、不首建。

**Architecture:** `m_MenuTextPool` 是最终存储边界；旧 `SettingsTextElement()` / `DoSettingsLabelStreamed()` 只保留为 settings scope wrapper。稳定文本定义为“文本内容和样式都稳定”的 UI 文案；状态化、动画化、运行时拼接、用户生成和实时数值文本继续走即时路径。不可见阶段预算预构建，visible 阶段只复用；miss/stale 记录为 coverage bug，并阻断 `targetSettings` 验收。

**Tech Stack:** C++, DDNet/QmClient `CMenus` / `CUi` / `CUIElement`, GoogleTest source-contract tests, existing `perf/*` telemetry, `qmclient_scripts/perf` TypeScript analyzer, CMake Windows build scripts.

---

## Scope And Definitions

优先级固定为：

1. `settings_subtab_switch / settings:tclient`
2. `settings_subtab_switch / settings:qmclient`
3. `ingame_esc_open`
4. 基础 settings 页回归

稳定文本必须同时满足：

- 文本内容不依赖实时状态、用户输入、列表数据、搜索结果、计数或时间。
- 样式不依赖动画颜色、彩虹颜色、hover-only 变体、未读 `[new]` 状态或其他可见阶段变化。
- 布局 key 能表达影响容器的尺寸信息，例如 max width、font size、align、compact mode、UI scale bucket。

明确排除：

- slider 当前数值、实时状态值、时间、FPS、ping、百分比、动态 badge。
- 输入框内容、搜索结果、用户生成名字、皮肤名、语言名、服务器/地图/demo 列表内容。
- QmClient `[new]` tab 文案、`QmNewFeatureLabel(...)` 组合文本、彩虹/动画颜色 module title。
- 任何无法稳定复用 style fingerprint 的文案，除非先拆成稳定 label 和动态 value。

## Invariants

- visible settings render 不创建稳定文本 container，也不重建 stale container。
- `RenderSettingsTClient(..., true)` / `RenderSettingsQmClient(..., true)` 可以作为既有资源/section 行为存在，但不能作为文本池预构建路径。
- `PrewarmVisibleSettingsResources()` 不能调用真实页面 render 来补文本。
- miss 与 stale 分开记录；两者都阻断 `targetSettings` 验收。
- `m_SettingsTextPool` 不再独立存在；如保留名称，只能是通向 `m_MenuTextPool` 的 wrapper。
- plan item 不保存悬垂 `const char *`；可跨帧保存的字段必须 owning。
