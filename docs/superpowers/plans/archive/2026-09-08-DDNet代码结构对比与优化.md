# DDNet 代码结构对比与优化

用户在本轮明确要求比较本项目与官方 20.0 及之后的代码结构，并进行适用优化。本工作是现有上游同步任务的扩展，保留已经完成的 RCON、JSON 修复以及旧台账复核，不恢复已放弃的干净基线重构。

## 对比方法

以官方 20.0、固定官方 master `59968143f`、本地当前实现三方比较。文件是否存在只是线索，必须继续查符号位置、调用关系、源码历史、构建登记、本地定制和测试依赖。同名文件内部结构差异也需检查，不能只交付文件列表。

适合的纯搬移/职责拆分以当前本地函数为源，保留函数体及运行行为；不能用官方整文件覆盖 QmClient 实现。新增平台后端、协议、snapshot、预测和输入时序仍按原范围边界单独确认。允许为已确定的文件拆分调整 CMake 源登记和测试的真实源码路径，不借机改构建或测试语义。

## 初始清单

[结构差异表](2026-09-08-DDNet代码结构差异.tsv) 基于三个提交树，只列路径存在性不同的 C/C++/Rust 文件。490 个路径差异包括官方当前独有 37、本地独有 445、官方删除 7、其他 1。计数不是功能数量，也不代表优劣或缺失；工作树新增文件和同名文件内部差异由后续复核补充。

优先检查的组：

1. UI popup：官方 `f1dfd5187` 将 633 行实现逐字从 ui.cpp 拆到 ui_popups.cpp，本地同类实现包含约 900 行及 Qm 定制。检查 static helper 和调用依赖，按本地实现搬移。
2. 设置页：官方按 appearance/credits/ddnet/general/graphics/language/player/sound/tee/tee7 拆分；QmClient 自有卡片结构需逐模块匹配，不能按文件名机械拆分。
3. base/system：官方 aio/bytes/io/net/os/process 已拆分；核对本地 system.cpp、其他 base 文件和 Rust bridge 的实际归属后制定批次。
4. 渲染后端：backend_threaded、EGL 与 map renderer 涉及新能力和本地 Metal，不属于自动纯搬移。
5. 其他：font_icons、multiview、quad_art/tile_art 命名、PCH、HTTP Emscripten、sixup snapshot 路径分别判定，不把路径缺失当成实现缺失。
