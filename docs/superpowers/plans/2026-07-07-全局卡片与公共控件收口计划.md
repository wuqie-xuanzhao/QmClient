# 全局卡片与公共控件收口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 Settings/QmClient/TClient 等设置页统一到 QmClient 页面当前卡片、滚动条、输入框和下拉框公共组件体系，并清理旧的分叉路径。

**Architecture:** 先建立公共 UI primitive（card layout/shell、scroll preset、text field、dropdown policy），再逐页迁移调用点，最后删除旧 helper 和旧测试期望。全局卡片 Model 与跨页面组件编辑器沿用 `docs/superpowers/specs/2026-06-29-全局卡片架构-统一拖拽与持久化.html` 和 `docs/superpowers/specs/2026-06-29-全局卡片-组件编辑器与stableId设计.md` 的目标设计；本计划优先收口视觉/交互公共路径，避免继续出现“两套卡片/两套滚动/两套 dropdown”。

**Tech Stack:** C++17 · DDNet/QmClient immediate UI · CMake/Ninja · GoogleTest `testrunner` · `qmclient_scripts/gate/check_gate.py`

## Global Constraints

- 不修改 DDNet 网络协议、Demo/皮肤/地图格式、物理、预测、碰撞、快照、输入语义或排名可达性。
- QmClient 配置项统一 `qm_` / `Qm` 前缀；不新增 `cl_` 前缀配置。
- 注释使用中文；保持原文件缩进、换行符和周围 DDNet 风格。
- 生产代码修改必须 TDD：先写失败测试并观察红灯，再做最小实现。
- 同一 `cmake-build-release` 目录中的 `testrunner`、`run_cxx_tests`、`run_rust_tests`、`game-client` 串行执行。
- 当前工作区已有 UI 相关未提交改动；执行计划时不得回退用户或先前代理的无关改动。
- 子代理只能做直接任务，不得再派发子代理；子代理没回不得声称 review 完成。
- 视觉目标以当前 QmClient/栖梦页面卡片基本参数为准：padding、radius、border/highlight/fill、竖向滚动条宽度和页面 card spacing 必须同源。

## 目标模式

本节是最终态判定标准。执行任务时不能把“局部看起来接近”当作完成；只有下面的目标模式在代码、测试和人工视觉证据上同时成立，才算这一轮公共 UI 收口完成。

### 1. 总体目标

- Settings 体系只能保留一套“设置卡片”视觉和交互模型。QmClient 当前页面是样式权威，其他设置页只能复用它的公共 helper 和参数链路。
- 卡片、滚动条、输入框、dropdown 都必须从“页面各自手写”收口为公共 primitive。页面代码负责业务内容，不负责重新定义 chrome、padding、滚动条宽度、popup 裁剪或输入框外壳。
- 全局卡片 Model、跨页面注册、搜索、拖拽、持久化继续对齐 `docs/superpowers/specs/2026-06-29-全局卡片架构-统一拖拽与持久化.html` 和 `docs/superpowers/specs/2026-06-29-全局卡片-组件编辑器与stableId设计.md`。本计划重点收口已经暴露出来的视觉和交互分叉，不能替代 B1/B2 Model 后续任务。
- 迁移过程中不接受“看起来相似但两套实现并存”。如果旧 helper 仍可被业务页面调用，就视为未完成。

### 2. 公共卡片契约

- 唯一视觉参数链路：

```text
ui_widget::QmClientCardProps()
  -> CMenus::QmSettingsCardStyle(float UiScale)
  -> CMenus::QmSettingsCardLayout(...)
  -> CMenus::RenderQmSettingsCardShell(...)
```

- `QmSettingsCardLayout(...)` 只负责几何：外框、内容区、标题区、拖拽把手区。所有页面拿到的 `ContentRect` 必须来自这个 helper，不能再 `Card.Margin(QmCardStyle.m_Padding, ...)` 手写一遍。
- `RenderQmSettingsCardShell(...)` 只负责公共外壳：背景、边框、highlight、标题预留、拖拽把手。业务页面只能在 `m_ContentRect` 内画内容。
- 双列布局、列间距、卡片间距和 shared deck 的 card width 由公共 deck/card layout 决定。Graphics、TClient、Search 等页面不得通过私有 wrapper 或强制单列让宽度偏离 QmClient 页面。
- 拖拽代理、drop indicator、让位动画、释放动画和持久化使用同一套 card item 注册信息。TClient 主设置页不得保留独立 drag wrapper 或旧 cache card layout。

### 3. 页面迁移目标

- QmClient：保留当前页面作为视觉基准，但自身也必须走公共 card shell，不允许继续存在本地 `RenderQmSettingsGlassCard + Margin` 路径。
- Search：`Search - 搜索` 是独立设置页，展示所有可搜索全局卡片。QmClient 原页面不保留本地搜索栏，也不渲染局部搜索结果。
- Search 结果：包含 `qm:`、`tclient:`、`deck:` 等所有可见全局卡片，不只包含 QmClient 本地卡片；结果卡片走公共 shell。
- TClient：主设置页、ChatBinds、BindWheel、StatusBar 等卡片迁移到公共 shell/deck。`TClientCacheSectionBoxRect`、`InsetTClientCacheSectionContent`、`DrawTClientCacheSectionBox` 必须删除。
- Settings 常规页：Graphics、Sound、DDNet、Appearance 等页面的手写卡片逐步清空；局部高度可以保留，卡片外壳、padding、拖拽/标题区域不能私有化。

### 4. 公共滚动条目标

- 设置页竖向滚动条宽度、边距、轨道和 thumb 基础参数以 QmClient 页面为准。
- 公共滚动条必须提供大/中/小 preset。业务页面按语义选择 preset，只允许覆盖 `m_ScrollUnit` 这类行为参数；不能手写与 QmClient 风格冲突的 thickness/margin。
- 横向和竖向滚动都通过同一类公共参数结构表达。底层通用控件可以维护基础默认值，但设置页业务代码不能绕开公共 preset。
- 页面滚动区、长列表 dropdown、短选项 dropdown 的滚轮归属必须明确，不能用“滚轮时关闭 dropdown”规避滚动路径问题。

### 5. 公共输入框目标

- 搜索框、纯文本输入框、带清除按钮输入框共享同一 visual shell、placeholder、focus/hover 动画和内边距规则。
- 输入框内部不能出现双层深色 plate、左右短一截、placeholder 和真实文本重影。
- 编辑能力按真实输入框验收：点击定位光标、拖拽选择文本、选中文本后输入替换、点击外部失焦并保留值。
- 双击全选如果 DDNet 基础 editbox 已支持则直接验收；如果基础层当前不支持，必须记录为 base editbox 行为缺口，不能把视觉收口包装成编辑能力完成。

### 6. Dropdown 目标

- Dropdown 分为两类策略：
  - 长列表型：例如 Tee 国旗选择。选项多，popup 内部需要滚动条，滚轮优先用于 popup 内容。
  - 短选项型：例如 Graphics 窗口模式。选项少，默认不显示内部滚动条；打开期间页面滚动不关闭 popup。
- 短选项型也必须有最大可见高度上限；超过上限、屏幕空间不足或父容器 clip 压缩时，自动切换为 popup 内部滚动。
- Popup 位置以触发控件当前 rect 为锚点，滚动后仍跟随控件真实位置计算，不能使用过期视窗绝对坐标。
- Popup 的绘制、hit-test 和 wheel hot region 必须尊重父 clip/遮挡关系：上方应被父容器裁掉的部分不能覆盖上层内容，也不能响应鼠标。
- Dropdown 打开期间，滚轮行为不能关闭 dropdown。关闭只允许由选择、Esc、外部点击或原有明确关闭路径触发。

### 7. 必须清理的旧路径

- `TClientCacheSectionBoxRect`
- `InsetTClientCacheSectionContent`
- `DrawTClientCacheSectionBox`
- QmClient/Search/Appearance 中的 `RenderQmSettingsGlassCard(...)` 后手写 `Margin(...)` 内容区路径
- 设置页业务代码里的本地 scrollbar thickness/margin
- 为解决 dropdown 滚轮而关闭 popup 的路径
- TClient 或其他页面本地 drag wrapper、proxy、drop indicator 与 shared deck 分叉的路径

### 8. 完成证据

- 结构测试证明所有主要设置页卡片入口调用公共 card helper，旧 TClient cache card helper 不存在。
- 聚焦测试覆盖 Search 全局结果、dropdown clip/wheel 策略、输入框共享 shell、滚动条 preset、shared deck 迁移。
- `run_cxx_tests` 通过。
- `check_gate.py --mode default` 通过，除非用户明确只要求文档或调查。
- 人工视觉检查覆盖至少：QmClient、Search、Graphics、Appearance、TClient 主设置页、Tee 国旗 dropdown、Graphics 窗口模式 dropdown。

### 2026-07-07 架构返工计划：清退旧层，而不是继续套壳

本节覆盖最新人工反馈：其他页面卡片仍明显不同于栖梦页面、公共组件只是套在旧玻璃/旧拖拽/旧布局外面、以及栖梦页面文本字号比其他页面小一号。后续实现必须优先执行本节；未完成前，不得再把“结构完成”写成卡片体系完成。

#### 当前根因判定

- 公共 `RenderQmSettingsCardBackdrop(...)` 仍通过 `ui_widget::DrawCard(...)` 画卡片；栖梦页面主卡片本地 `DrawGlassCardBackground` 使用另一套 1.5px hairline + 内缩主体填充 + 可选磨砂叠加。这导致“公共卡片”与栖梦卡片实际不是同一套绘制路径。
- `ui_widget::DrawCard(...)` 本身保留 shadow、外扩 border、top highlight 等旧 card chrome，哪怕 `RenderQmSettingsCardBackdrop(...)` 传入 `m_Elevation = 0`，仍不是栖梦页面的卡片结构。
- `RenderSettingsCardDragHandle(...)` 仍画右上角 2x3 dots。用户截图中的点状 handle 是旧实现信号，不能作为目标态保留给设置页主卡片。
- Controls 页 `RenderSettingsBlock(...)` 曾直接绘制 `ui_token::color::SURFACE_GLASS/SURFACE_ELEVATED` 和本地 top highlight，是“控制页面仍是液态玻璃”的直接来源；Controls 也必须走公共 `RenderQmSettingsCardShell(...)`，不能作为例外。
- 拖拽不一致不能用“去掉 dots”关闭。除了 handle 视觉外，还必须审计页面是否保留私有 drag wrapper、proxy、drop indicator、layout transition 和释放动画路径。
- QmClient 页面本地字体常量为 `LgHeadlineSize = clamp(14 * UiScale, 12, 14)`、`LgBodySize = clamp(12 * UiScale, 10, 12)`、`LgLineHeight = clamp(20 * UiScale, 16, 20)`。其他页面大量使用 14/15/16 等默认字号，视觉上比栖梦页面大一号。
- 多个页面虽然调用了 `RenderQmSettingsCardShell(...)`，但仍保留页面本地 wrapper、内容 panel、固定间距、固定宽度或旧 section/card deck 计算，导致卡片靠左、右列为空、顶部边框被裁、TClient 上下间距丢失。
- Search 页面当前结果卡片仍偏“摘要卡”：渲染 tab/destination/stableId 等元信息，容易出现英文、重复文本和灰蒙蒙的非栖梦卡片观感。目标是搜索页使用同一 settings card shell 和栖梦字号，且内容只展示用户需要识别/进入的最小信息。

#### 目标口径补充

- `QmClient/栖梦页面` 不是“参考样式”，而是代码基准。公共卡片绘制实现必须从栖梦当前卡片提取，栖梦自身也改用该公共实现，删除本地 `DrawGlassCardBackground` lambda。
- 设置页主卡片不得再调用或间接调用 `ui_widget::DrawCard(...)` 作为外壳；`DrawCard(...)` 可保留给非设置页或底层普通容器，但不能作为 Settings card shell 的实现。
- 设置页主卡片不再显示 2x3 dots 旧拖拽 handle。拖拽热区和视觉提示需要对齐栖梦页面当前行为；如果栖梦页面没有显式 dots，其他页面也不能保留 dots。
- 所有 Settings/QmClient/TClient/Search/Appearance/Graphics/Sound/DDNet 页面正文基础字号统一使用栖梦基准：正文 10-12、标题 12-14、提示不大于正文。字号必须通过公共 settings typography helper 派生，页面不能散写更大的默认字号。
- 页面布局参数统一从一个 settings page layout helper 取得：顶部 inset、左右 inset、卡片最大宽度、双列阈值、列间距、卡片间距、滚动条预留宽度、顶部导航与内部滚动区域规则、搜索页顶部卡片 inset 都不得页面私有化。页面不得根据自身宽度重新推导这些值。
- 卡片内部元素也必须从同一个 metrics/helper 取得：卡片标题大小、标题彩虹颜色策略、hover 时副标题/提示文本显示规则、行高、行间距、正文大小、提示文本大小、label 列宽、卡片 padding、正文区上下间距、控件间距都以栖梦页面当前值为基准。页面业务代码只能消费这些 token，不能再复制 `LgHeadlineSize`、`LgBodySize`、`LgLineHeight`、`LgLineSpacing`、`LgTipSize`、`LgLabelWidth`、`MarginSmall`、`LineSize` 等局部公式来排卡片内部内容。
