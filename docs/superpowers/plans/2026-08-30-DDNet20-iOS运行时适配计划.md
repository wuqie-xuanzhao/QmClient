# DDNet 20.0 iOS 运行时适配计划

> 目标更新（2026-09-01）：本计划记录的 SDL/OpenGL ES bring-up 仍是历史基础；后续主线改为 macOS/iOS 默认 `Release` 构建启用 Metal，详细执行边界见 `../plans/2026-09-01-QmClient-iOS-Metal默认Release适配计划.md`。

## 目标

在不改变 DDNet 协议、预测、地图格式或 QmClient 私有玩法语义的前提下，适配上游 iOS SDL/OpenGL ES 客户端。首个可交付版本必须能构建 iOS simulator app，并在后续真机验证通过后才考虑原生 Metal iOS 后端。

P2 已生成并检查设备 arm64、模拟器 arm64/x86_64 的依赖 `.xcframework`。这不是客户端可运行证据。

## 已确认边界

- 上游 `936f2b7c1` 是 SDL/OpenGL ES iOS 路径，CMake 链接 `Metal`/`QuartzCore` 是 SDL 平台依赖，不代表 QmClient 原生 Metal 后端可直接启用。
- 当前 macOS Metal 文件正在并行修改，P3 不修改 `src/engine/client/backend/metal/`，不把 `METAL` 打开，也不复用 macOS metallib。
- iOS 上游网络补丁的文件路径已分叉：当前网络实现在 `src/engine/shared/`，因此必须按本地所有权适配 socket 失效检测和恢复，不能照搬 `src/base/net.*` diff。
- 上游 iOS 的 `ddnet-libs` gitlink 是 `44aaf5da9ce0168fd45a71bbb879a8ecd2d4e2c7`；本地 fork 已以 `24a9a5e3c22f` 形成仅新增 iOS 资产的提交，主仓库当前 gitlink 指向该提交。
- iOS 的 deployment target 已按上游 App Store 校验修复提升为 `15.0`。SDL 2.32.10 在 Xcode 26 SDK 上有未守卫 `CAMetalLayer` 可用性警告。这是上游依赖告警，不得把它当作 QmClient 原生 Metal 已验证。
- 本地 `ddnet-libs` fork 只允许新增以下 iOS 资产：`curl/ios/libcurl.xcframework`、`freetype/ios/libfreetype.xcframework`、`opus/ios/libogg.xcframework`、`opus/ios/libopus.xcframework`、`opus/ios/libopusfile.xcframework`、`png/ios/libpng16.xcframework`、`sdl/ios/libSDL2.xcframework`、`sqlite3/ios/libsqlite3.xcframework` 和 `sdl/include/ios/`；MoltenVK、WebP 与既有 Windows 内容必须保留。

## 分批实施

### P3A：编译目标与包结构

状态：已完成并提交（`1eafa9ed3`、`e5325e77b`）；iOS bundle 的编译、链接和资源复制已验证，AppIcon 编译、安装与启动仍属于 P3C。

文件边界：`CMakeLists.txt`、`scripts/ios/`、`src/ios/`、`src/base/detect.h`、必要的 Apple/SDL 条件编译点、`ddnet-libs` gitlink。

1. 添加 iOS target 检测、iOS xcframework slice 搜索、系统 framework 链接与 Rust target 选择。
2. 添加 Xcode 生成脚本、Info.plist、AppIcon assets 和 iOS SDL app entry；bundle 内必须复制 `data/` 与 `storage.cfg`。
3. 让 iOS 使用 `CONF_PLATFORM_IOS`、GLES 默认和触控默认配置；不改 macOS/Android 的原有默认。
4. 首次 exit gate：Apple Silicon simulator 的 Xcode configure 与 `game-client` 编译；产物 bundle 含 data、storage.cfg、Info.plist 和 AppIcon。

已实现：iOS CMake target、xcframework slice 查找、Rust iOS target、SDL/GLES bundle、`src/ios/` entry、Info.plist、AppIcon assets、`data/`/`storage.cfg` 复制和 `CONF_PLATFORM_IOS`。`scripts/ios/cmake_ios.sh` 默认编译 asset catalog，并允许 `IOS_USE_ASSET_CATALOG=OFF` 仅用于没有 simulator runtime 时的编译/链接/资源诊断。

停止条件：无法以官方 gitlink 获取依赖；需要改动正在编辑的 Metal 文件；或本地 CMake/SDL 分叉使上游 target 结构不成立。

### P3B：生命周期、存储与网络恢复

状态：已完成并提交（`1eafa9ed3`、`e5325e77b`）；代码和 C++ 回归测试已通过，后台恢复仍需要 P3C 的 simulator/真机证据。

文件边界：当前网络 owner、`client.cpp/.h`、`input.cpp`、`fs`/`system` Apple 条件编译、通知与 URL/file viewing。

1. 后台前保存配置；前台后只在系统关闭 UDP socket 的确定信号下重建 socket，并保留主/分身重连语义。
2. iOS Documents storage、app bundle 当前目录、横屏 SDL hint、Files app 导出链接与通知依赖条件编译均采用最小平台分支。
3. 先添加 socket 失效检测的本地单元或源码合同测试，再接入 `CClient` 恢复；不得在没有真机证据时宣称后台恢复完成。

已实现：Documents storage、bundle current directory、CoreFoundation locale、semaphore、SDL autorelease pool、后台配置保存、横屏 hint、Files URL export、通知依赖条件编译。iOS UDP 仅在 `sendto` 失败且 `errno == EPIPE` 时标记 broken；`CClient` 在网络泵开始时检测、断连、关闭旧 socket，只有三个 client socket 都重建成功后才加载 DDNet/STUN 信息并恢复主连接，主连接 `NETMSG_CON_READY` 后再恢复 dummy。重建失败会保持离线，避免使用旧 broken socket 重连循环。

停止条件：触及协议、超时保护/预测语义而无法与上游等价说明；或不能为主/分身 reconnect 写出明确验证。

### P3C：simulator 与设备验收

状态：待执行。当前 `xcrun simctl list runtimes` 没有返回已安装 runtime，默认 `actool` 因此无法编译 asset catalog；必须先安装 simulator runtime。

1. Apple Silicon simulator：安装、启动、读取 bundle data、写入配置日志。
2. arm64 真机：签名后完成首次启动、触控、服务器连接、后台恢复、截图、退出和 Files 导出。
3. 有本地构建与真机证据后再适配 CI；不直接搬运上游 release workflow。

## 回滚

P3A 的回滚单位是 iOS-only CMake/entry/asset/gitlink 变更；不影响现有桌面 target。P3B 的 iOS 分支必须由 `CONF_PLATFORM_IOS` 包围，桌面网络与客户端流程不改变。
