## 背景

当前通知栏存在三类实现问题：

1. HUD 编辑器拿到的是固定容器宽度，而不是通知栏真实渲染包围盒，导致拖拽框过大，吸附和贴边判断失真。
2. 通知栏条目始终按“容器内右贴齐”布局，左贴边状态不会让通知真正从左侧长出。
3. 通知栏在 HUD 编辑器中的位置语义和实际渲染语义脱节，编辑器保存了位置，但通知自身没有原生配合左右生长方向。

## 目标

1. 通知栏向 HUD 编辑器上报真实可见区域，而不是固定占位宽度。
2. 通知栏支持完整左右布局语义：
   - 靠左时，从左向右生长；
   - 靠右时，从右向左生长；
   - 不贴边时，按屏幕中线决定更自然的左右方向。
3. 预览态、真实通知、多条堆叠、缩放和拖拽都走同一套几何逻辑。

## 非目标

1. 不改通知设置页结构。
2. 不改系统消息和 echo 路由规则。
3. 不新增通知栏专用配置项。
4. 不重做整个 HUD 编辑器的通用状态模型。

## 设计

### 1. 通知栏原生几何

通知栏渲染拆成两层：

- 固定变换矩形：
  - 继续作为 HUD 编辑器保存位置和缩放时的参考矩形。
- 内容可见矩形：
  - 按当前通知文本测量结果动态计算；
  - 宽度取当前可见通知中最宽的盒子；
  - 高度取当前可见通知实际堆叠高度。

HUD 编辑器只应对真实可见矩形做 hover、拖拽和缩放反馈。

### 2. 左右生长规则

通知栏新增明确的水平布局方向：

- 若当前可见区域贴左边，条目从左向右布局。
- 若当前可见区域贴右边，条目从右向左布局。
- 若当前未贴边，则按通知栏可见区域中心与屏幕中线比较：
  - 中心在左半屏，按左向右布局；
  - 中心在右半屏，按右向左布局。

这套方向不仅影响盒子位置，也影响可见矩形的 `x` 计算。

### 3. HUD 编辑器预览配合

HUD 编辑器需要提供一个“只计算、不注册、不应用 MapScreen”的预览变换接口，供通知栏在正式注册前判断：

- 当前元素经布局状态变换后的目标矩形；
- 当前是否贴左、贴右；
- 当前可见区域大致位于屏幕哪一侧。

通知栏先用这个预览结果决定水平布局方向，再把真实可见矩形传回正式 `BeginTransform(...)`。

### 4. 测试边界

本轮至少补这三类测试：

1. 内容可见矩形使用真实宽度，而不是固定容器宽度。
2. 左向右与右向左布局的盒子 `x` 位置不同，且都与各自锚点语义一致。
3. HUD 编辑器预览接口与通知栏布局方向配合后，不会回退到“始终右贴齐”。

## 验收标准

1. 通知栏在 HUD 编辑器里的拖拽框贴合真实内容宽高。
2. 把通知栏拖到左边后，通知条目从左边长出，不再保留左侧空白容器。
3. 把通知栏拖到右边后，通知条目继续从右边长出。
4. 通知栏放在左右中间附近时，布局方向会随左右半屏自然切换。
5. 现有通知消息分类、黑名单和 echo 行为不回归。
