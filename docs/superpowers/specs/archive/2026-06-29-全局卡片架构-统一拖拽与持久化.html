2026-06-29 · status: active · 来源：阶段 2 拖拽架构调研 + 让位动画实践 + 用户全局卡片持久化需求

现状问题：四套卡片实现并存（栖梦侧栏合批 / 单卡 underlay / Tclient deck / section_loader 通用层），两套拖拽范式（栖梦长按 0.3s / Tclient 已统一长按），两套持久化（QmSidebarCardOrder / qm_settings_card_order），让位动画框架在但效果不对（拖拽中 TargetRect 不变 → 无让位）。本规格定义全局统一架构。

1 · 设计目标

iPhone 主屏风拖拽 UX：长按 → 被拖卡跟手 + 其他卡实时让位（spring lerp）→ 松手归位 + 持久化。全局卡片管理：一套 Model 管所有设置页卡片，每页只筛选展示，拖拽改全局 → 跨页保留。

已确认愿景（用户 2026-06-29 确认）：全局卡片 = 跨页面组件编辑器。卡片是 first-class 全局组件，可在任意 tab/列/位置间排布迁移，tab 是可改的位置维度而非固有归属。全局单例 Model 是正确架构，不再标记为待验证。stableId 命名规范、默认值系统、稳定持久化模型的完整设计见 docs/superpowers/specs/2026-06-29-全局卡片-组件编辑器与stableId设计.md；卡片数量以 QmCardRegistry.cpp 当前注册表为准。
2026-07-07 目标模式补充：设置页还必须收口到一套公共 UI primitive：QmClient/栖梦页面是卡片视觉参数权威；卡片 shell/layout、竖向滚动条 preset、输入框 shell、dropdown policy 都必须同源。不能保留“看起来相似”的 TClient/Graphics/Search/Appearance 私有卡片路径。执行计划与验收台账见 docs/superpowers/plans/2026-07-07-全局卡片与公共控件收口计划.md。

2 · 全局卡片 Model（核心）

2.1 统一注册表

所有设置页卡片注册到同一个 qm_card_order::CModel（QmUi/QmCardOrderModel.h）。当前 SEntry 已包含 {m_pStableId, m_pDefaultTab, m_Column, m_OrderInColumn}；tab 是可变位置维度，运行时由全局模型保存。目标态每卡声明 {stableId, tab, column, order}：

  • stableId：全局唯一（如 "qm:visual:card_appearance"、"tclient:visual-font-cursor"）
  • tab：当前位置页面/画布（"visual" / "tclient" / "graphics" / "appearance-hud" 等）
  • column：列（Left / Right / Full）
  • order：列内顺序

页面渲染时 Model.ColumnIndices(tab, column) 筛选本页卡片。该 API 已存在；仍需逐页审计生产渲染是否已经全部从全局模型读取，而不是继续读页面私有顺序结构。

2.2 持久化

单一 config qm_global_card_order（格式 <stableId>|<tab>|<col>|<order>;，用 | 分隔字段——stableId 含 :，用 : 分隔会歧义；详见设计文档 §5.2），替代当前的 QmSidebarCardOrder + qm_settings_card_order 两套。CModel::Parse 容错（未知 id 跳过），CModel::Serialize 写入。用 CModel::IsDirty() 触发序列化落盘（替代无变化帧重复重建字符串）。当前已有 Qm adapter 辅助，验收重点是确认生产同步路径不会覆盖非 Qm 命名空间条目，也不会在普通渲染帧无条件序列化。

2.2.1 迁移（一次性，需覆盖边界）

首次启动检测旧 QmSidebarCardOrder / qm_settings_card_order，合并到 qm_global_card_order。这是会丢用户布局的高风险操作，必须覆盖以下边界：

  • 幂等：新增 qm_card_order_migrated 标志（bool config）。已迁移则跳过，避免新旧并存时重复合并冲突；迁移成功后置位。
  • stableId 映射：栖梦旧格式 key:col:order;（如 chat_bubble:1:0;，无 page）需映射到新 id:page:col:order;。维护一张"旧 key → 新 stableId + page"映射表（在 B1 落地），映射失败的 key 按保留原列原序、page 取该卡默认归属页兜底，不能丢弃。
  • 格式兼容：CModel::Parse 按分隔符区分新旧——含 | 走新格式（id|tab|col|order 四段），否则按旧 : 三段（栖梦 key:col:order / Tclient id:col:order）回退；字段数不足或非法值跳过该条不中断解析。
  • buffer 容量：MACRO_CONFIG 字符串是定长 buffer。卡片从 ~37 扩到全局 80+，序列化串约翻倍。B2 需估算 qm_global_card_order 容量并校验 Serialize 不截断（参考现有 sizeof(g_Config.m_QmSidebarCardOrder)）。
  • 降级回退：旧版不读 qm_global_card_order。需说明"新版→旧版→新版"往返会触发重新迁移（幂等标志保护），可接受顺序短暂丢失，不可静默。

迁移完成后旧 config 不立即删除（保留一个版本作为回滚锚点），下一版本再清理。

用户发散："持久化是全局的，每个页面只是展示卡片，可以随意移动组合" — 本规格采纳：卡片是全局资源，页面是展示层（filter），拖拽改全局 → 所有页生效。

3 · 让位动画（iPhone 风）

当前实现口径（2026-07-02）：本章 3.1–3.4 记录的是原始「拖拽中实时让位」方案与问题分析。实际代码当前采用更保守的手机主屏替代式策略：拖拽中保持正常卡片间距，不插入额外占位，不移动其他卡；当标题栏锚点停留到目标卡片位置超过 dwell 阈值后形成 drop candidate；松手时提交布局，再由 QmUi FLIP 负责从当前显示 rect 平滑过渡到最终 target rect。这样避免拖拽态间距突变、被拖卡遮蔽和上下闪动问题。若未来重新启用拖拽中实时让位，必须重新评估本章的预览 TargetRect 方案，并以正常卡片间距一致性为硬约束。

3.1 当前问题

让位是 per-card DisplayRect lerp 追 TargetRect（Disp += (Target - Disp) * LerpT，LerpT=0.25，见 menus_qmclient.cpp:7899），不存在"Column 偏移 offset"变量。拖拽中 UpdateDropPreview 只算落点 DropIndex，不改 m_OrderInColumn、也不重排布局 → 布局每帧算出的 TargetRect 不含被拖卡的腾位 → 其他卡的 DisplayRect 追一个静止目标 → 全部停在原位 → 无让位视觉效果。松手 CommitDropPreview 才改 order → TargetRect 突变 → 其他卡从原位开始 lerp 让位、被拖卡从鼠标位置 lerp 到最终落点（松手即收敛无跳变，但让位滞后到松手才发生）。

3.2 原方案：拖拽中实时预览布局

UpdateDropPreview 不只算 DropIndex，而是生成一个预览布局（PreviewLayout）：

  1. 基于当前全局 Model + 被拖卡的新位置（DropColumn + DropIndex），计算每张卡片的预览 TargetRect
  2. 预览 TargetRect 写入 ModuleCards[i].m_TargetRect（不 commit 到 Model，只渲染层预览）
  3. AnimateModuleCardPositions lerp DisplayRect → 预览 TargetRect
  4. 其他卡的 DisplayRect 处于 lerp 中间位置 → 实时滑动让位（不需要 Column 级 offset，每卡各自追自己的预览目标）

松手 CommitDropPreview → Model.Move（commit 预览到真实数据）+ Serialize 落盘。

3.3 当前实现：松手提交 + FLIP 归位

当前代码不再依赖局部 per-card lerp 手写速度状态，而是使用 QmUi 通用布局过渡层：

  1. 拖拽中被拖卡通过 SyncLayoutTransition 同步到鼠标/标题栏锚点对应的显示位置，避免 FLIP 与手动拖拽冲突。
  2. 未拖拽卡片在拖拽过程中保持正常目标布局，不因占位产生额外间距。
  3. 松手 CommitDropPreview 后更新卡片 order；下一帧每张卡调用 ResolveLayoutTransition(..., ui_token::motion::CARD_REORDER)，由 tree-owned cache 对稳定 NodeKey 的前后 rect 做 POS_X/POS_Y 过渡。
  4. 被拖卡释放路径从当前显示 rect 过渡到最终 target rect；其他受影响卡从旧显示 rect 过渡到新 target rect。

实现要点：保持被拖卡当前显示位置，不在松手帧硬切坐标；只动画位置，不动画宽高；正在拖拽的节点跳过自动 FLIP，由拖拽路径手动 sync。

技术要点：预览布局计算需要在 UpdateDropPreview 中模拟 "如果被拖卡在 DropIndex 位置，其他卡的 rect 会怎样"。当前栖梦的 ColumnSplitX + 遍历 prev/next 逻辑可以复用，但需要输出每张卡的 TargetRect（不只是落点 line）。

3.4 让位边界情况

预览布局计算需显式覆盖以下场景（核实自 menus_qmclient.cpp 现状）：

  • 跨列拖拽：CommitDropPreview(:7824-7849) 已支持跨列 erase+insert，但拖拽中实时跨列让位需同时算源列腾位 + 目标列插入两列的预览 TargetRect，不能只算单列。
  • Full 列模块：:7795 if(m_Column==Full) return false——Full 卡不拖不让位。全局 Model 里 Full 卡的 column 取值与跨页处理需在 B1 明确（建议 Full 卡不进 page filter 的可重排集合）。
  • 搜索过滤态：:7914 HasModuleSearch 时 ResetModuleDragState（禁拖）。预览布局应尊重过滤后的可见集，被过滤掉的卡不参与让位。
  • 折叠卡高度（路线图阶段 5 qm_settings_card_collapsed）：折叠卡 TargetRect 高度变小，预览布局须用当前实际折叠高度，不能假定全展开。
  • 页面切换抖动：全局 Model 下切页时旧页 ModuleCards 还在 lerp 收敛、新页 TargetRect 突变 → 需切页时重置 DisplayRect 初值（走 :7892 保护）或暂停一帧 lerp，避免抖动。
  • 性能（缓存）：UpdateDropPreview 每帧重算所有卡预览布局——DropIndex/被拖列不变时应缓存复用，仅在变化时重算，避免每帧全量 O(N)；同时 TargetRect 每帧变会影响卡片背景合批 cull（:947），需确认合批稳定。
  • 动画曲线：让位 lerp 当前用固定 LerpT=0.25 指数衰减（≈临界阻尼，够用）。若快速连续拖拽/跨列出现抖动，改用 ResolveUiAnimValue 的 SPRING+MERGE_TARGET 重载（note.md 05:06 结论：改 target 不重启不丢 velocity，TWEEN 会抖）。

5 · 视觉统一（阶段 4 复用）

所有设置页卡片统一到 QmClient/栖梦页面当前样式参数。当前收口路径采用 QmSettingsCardStyle()、QmSettingsCardLayout()、RenderQmSettingsCardShell() 作为设置页公共 card shell/layout。页面业务代码只在 m_ContentRect 内画内容，不得私有化 padding、radius、border、drag handle、drop indicator 或 card width。

  • 卡片：QmClient、Search、Graphics、Appearance、TClient、deck 页必须同源；旧 TClientCacheSectionBoxRect / InsetTClientCacheSectionContent / DrawTClientCacheSectionBox 类路径必须删除。
  • 滚动条：设置页竖向滚动条宽度、轨道、thumb、边距以 QmClient 页面为准，公共 large/medium/small preset 是唯一入口。

7 · 约束

  • 不改 DDNet 上游协议 / 物理 / 预测 / 碰撞
