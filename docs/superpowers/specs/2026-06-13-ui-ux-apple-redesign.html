0 · 设计哲学：macOS 桌面参考

1 · 主题系统：颜色自定义 核心新增

现状最大的脱节：QmClient 已有完整的主题色配置——g_Config.m_QmUiColor（默认 0xE4A046 琥珀色），用户可在设置页通过 ColorPicker 自由修改（menus_settings.cpp:3067）。DDNet 原生菜单已全面接入（menus.cpp:124 的 MenuUiColorSurface、MenuUiColorAccent 等十余处）。但 QmUi 组件层完全没接入——UiTokens.h 中的 ACCENT_PRIMARY 是硬编码 #66C2F5 蓝色，与用户配置的琥珀色毫无关系。

1.1 现有主题色管线（已成熟）

// menus.cpp:122-143 — 已有的 HSL 色彩衍生管线
ColorRGBA MenuUiColorSurface(float AlphaScale, float ColorScale) {
    ColorHSLA UiHsla(g_Config.m_QmUiColor);        // 解码用户选的色
    UiHsla = UiHsla.UnclampLighting(0.42f);         // 统一亮度
    const ColorRGBA UiColor = color_cast<...>(UiHsla);
    return ColorRGBA(
        UiColor.r * ColorScale,                      // 色调缩放
        UiColor.g * ColorScale,
        UiColor.b * ColorScale,
        UiColor.a * UiAlpha * AlphaScale);           // 透明度叠加
}

ColorRGBA MenuUiColorAccent(float AlphaScale) {
    ColorHSLA UiHsla(g_Config.m_QmUiColor);
    UiHsla = UiHsla.UnclampLighting(0.48f);          // accent 更亮
    // ...
}

这个管线已经很强大：一个 m_QmUiColor HSLA 色码，通过亮度统一（UnclampLighting）、色调缩放（ColorScale）、透明度缩放（AlphaScale × m_QmUiOpacity），衍生出 surface、accent、hover、dim 等全套变体。问题是 QmUi 组件层绕过了它。

1.2 方案：QmUi Token 层接入主题管线

核心改动：将 UiTokens.h 中 ACCENT_PRIMARY 等硬编码 constexpr 改为从主题色派生的函数，默认值保持不变（向后兼容），运行时从 m_QmUiColor 读取。

▼ 现状 (UiTokens.h)

inline constexpr ColorRGBA ACCENT_PRIMARY{0.4f, 0.753f, 0.957f, 1.0f};

硬编码蓝色 #66C2F5，与用户主题色无关

compile-time，无法运行时改变

▲ 目标

ColorRGBA AccentPrimary(); — 运行时从 m_QmUiColor 派生

用户改主题色 → 所有 accent 组件即时联动

默认值 = m_QmUiColor 当前值

1.2.1 新增 QmThemeRuntime.h — 运行时主题解析器

// src/game/client/QmUi/QmThemeRuntime.h
#pragma once
#include "UiTokens.h"
#include 
#include 

namespace qm_theme_runtime
{
// 从 m_QmUiColor 派生的 QmUi accent 色——对标 MenuUiColorAccent
inline ColorRGBA AccentPrimary()
{
    ColorHSLA Hsla(g_Config.m_QmUiColor);
    Hsla = Hsla.UnclampLighting(0.48f);
    return color_cast(Hsla);
}

inline ColorRGBA AccentHover()
{
    ColorHSLA Hsla(g_Config.m_QmUiColor);
    Hsla = Hsla.UnclampLighting(0.55f);  // 更亮
    return color_cast(Hsla);
}

inline ColorRGBA AccentPress()
{
    ColorHSLA Hsla(g_Config.m_QmUiColor);
    Hsla = Hsla.UnclampLighting(0.40f);  // 更暗
    return color_cast(Hsla);
}

inline ColorRGBA AccentDim(float AlphaScale = 0.18f)
{
    return AccentPrimary().WithAlpha(
        std::clamp(AccentPrimary().a * AlphaScale, 0.0f, 1.0f));
}

// macOS material surface — 主题色 tint 叠加到半透明背景
inline ColorRGBA MaterialSurface(float AlphaScale = 1.0f, float ColorScale = 0.42f)
{
    ColorHSLA Hsla(g_Config.m_QmUiColor);
    Hsla = Hsla.UnclampLighting(0.42f);
    const ColorRGBA C = color_cast(Hsla);
    const float UiAlpha = g_Config.m_QmUiOpacity / 100.0f;
    return ColorRGBA(
        std::clamp(C.r * ColorScale, 0.0f, 1.0f),
        std::clamp(C.g * ColorScale, 0.0f, 1.0f),
        std::clamp(C.b * ColorScale, 0.0f, 1.0f),
        std::clamp(C.a * UiAlpha * AlphaScale, 0.0f, 1.0f));
}
} // namespace qm_theme_runtime

1.3 主题色影响范围

所有引用 ACCENT_PRIMARY 的 QmUi 组件改为调用 qm_theme_runtime::AccentPrimary()：

ACCENT_PRIMARY_HOVERAccentHover()Button hover, ListItem hover
ACCENT_PRIMARY_PRESSAccentPress()Button active
ACCENT_PRIMARY_DIMAccentDim()SecondaryButton hover, ListItem 选中
SURFACE_MATERIALMaterialSurface()DrawCard, Modal, List 容器
向后兼容策略：不删除 UiTokens.h 中的 constexpr——它们作为编译期 fallback 默认值保留。新增 QmThemeRuntime.h 提供运行时覆盖路径。组件层逐个迁移调用点。未迁移的组件继续用 constexpr，不会 break。

1.4 设置页 UI — 主题色选择器

设置页已有 ColorPicker（menus_settings.cpp:3067），无需新增 UI。用户改色的流程：

  1. 设置页 ▸ UI Color ▸ ColorPicker 改色 → m_QmUiColor 更新

1.5 macOS material 透明度控制

macOS 提供 Reduce Transparency 与多层 material 语义。QmClient 已有 QmUiOpacity（0-100），当前仅影响 DDNet 原生面板。扩展方案：

配置项当前用途扩展用途
QmUiOpacityDDNet 原生面板 alpha（menus.cpp:128）同时驱动 QmUi material surface 的 alpha（MaterialSurface() 内已含 UiAlpha）

用户降低透明度时，material 表面变得更不透明（更接近 macOS 的 "reduced-transparency" 高对比模式），提升文字可读性。这是对 macOS Reduce Transparency 的等价映射。

// UiButtons.cpp — DoStyledButton() 内

float Scale = 1.0f;
if(Ctx.m_pAnim != nullptr)
{
    const uint64_t Key = BuildUiAnimNodeKey(Ctx.m_ScopeHash ^ 0xBEEFull,
        reinterpret_cast(pBtn));
    Scale = ResolveUiAnimValue(*Ctx.m_pAnim, Key,
        EUiAnimProperty::SCALE,
        Pressed ? 0.96f : 1.0f, /* SNAPPY spring */);
}
CUIRect Scaled = Rect;
const float Dw = Rect.w * (1.0f - Scale);
Scaled.x += Dw * 0.5f;
Scaled.w -= Dw;

6.5.2 L0 Root Panel — 设置页整体卡片化 关键

现状问题：设置页的导航栏（TabBar）和内容区（MainView）是两个独立矩形，各自 Draw() 各自 Margin()（menus_settings.cpp:4549-4551）。它们之间有 10px 缝隙但不是统一的容器。没有外部呼吸边距——内容紧贴屏幕边缘。

目标：导航栏 + 内容区合并为一个统一面板，面板外围留呼吸边距（20pt），内部用分隔线区分导航和内容，而非两个独立卡片。

6.5.3 L1 Section Card — 设置内容模块化 核心

目标：每个设置分组（"游戏"、"客户端"、"画面"）用一个 DrawSection 卡片包裹，内部行用 DrawInsetGroup 组织。

9 · SDF 抗锯齿圆角

CUIRect::Draw() → DrawRectExt4() 三角扇近似圆角，无 MSAA 时锯齿。SDF shader 可实现亚像素平滑。

// data/shader/ui_sdf_rect.frag
float sdRoundRect(vec2 p, vec2 halfSize, float r) {
    vec2 q = abs(p) - halfSize + r;
    return min(max(q.x, q.y), 0.0) + length(max(q, 0.0)) - r;
}
void main() {
    vec2 center = v_LocalPos - u_RectSize * 0.5;
    float d = sdRoundRect(center, u_RectSize * 0.5, u_Radius);
    float aa = fwidth(d);
    float shape = 1.0 - smoothstep(-aa, aa, d);
    FragClr = vec4(u_Color.rgb, u_Color.a * shape);
}
前置：需 GL_OES_standard_derivatives（fwidth）。确认 DDNet GLES 后端支持，否则降级为固定 1px AA。渐进替换：仅 QmUi 组件层，不动全局 CUIRect::Draw()。

现状问题：data/qmclient/icons/ 已有图标管线，但存在三个核心缺陷——
(1) 格式落后：普通 RGBA PNG 光栅图集（1x/2x/4x 三倍率），缩放时锯齿明显；
(2) 图标丑陋：当前 8 个图标的视觉质量粗糙，曲线不流畅，边缘锯齿；
(3) 无 SDF 采样：RenderIcon()（qm_icon_manager.cpp:256-276）用标准 QuadsBegin + alpha blend，与 text.frag 的 SDF 管线完全不沾边。

10.2 目标：MSDF (Multi-channel Signed Distance Field)

将构建期 PNG 光栅化替换为 MSDF 烘焙。运行时用 SDF 采样 + smoothstep 亚像素平滑，在任意 cl_ui_scale 下输出锐利图标，并支持 shader uniform 实时改色。

10.2.1 MSDF 原理简述

普通 SDF 用单通道记录"像素到形状边缘的有向距离"。MSDF（多通道）用 RGB 三通道分别记录三组边缘的 SDF，取中值——在尖角（如星形顶点）处比单通道 SDF 精度高一个量级，且图集尺寸更小。

10.3 构建期：MSDF 图集烘焙

步骤说明
1. 扩充图标集从 Phosphor Icons（MIT，9000+ 图标，6 字重）挑选全套图标。当前 8 个 → 目标 40+ 个，覆盖：导航（caret-left/right/up/down, arrow-*）、操作（plus, minus, x, check, trash, pencil-simple, copy, share-network）、状态（star, heart, eye, eye-slash, bell）、媒体（play, pause, magnifying-glass, funnel）、设置（gear, sliders, palette, info）
2. SVG 源文件data/qmclient/icons/src/*.svg，Phosphor 原生 256×256 viewBox。每字重一个子目录：src/regular/、src/bold/、src/fill/、src/light/
3. MSDF 烘焙用 msdf-atlas-gen 批量生成：
msdf-atlas-gen -type msdf -format png -json ...
产物：单张 qm_icons_msdf.png（RGB 三通道）+ qm_icons_msdf.json
4. 构建脚本qmclient_scripts/build_sdf_icons.py 封装上述命令。开发者只需往 data/qmclient/icons/src/ 丢 SVG 然后跑脚本

为什么不再需要 1x/2x/4x 三套：MSDF 是矢量距离场，一张图集在任意缩放下都锐利。DPI 自适应逻辑（PreferredAtlasScale() :131-138）可简化为始终加载单张 MSDF 图集。

10.4 运行时：SDF 采样渲染

10.4.1 新增 SDF 图标 Fragment Shader

不能直接复用 text.frag——字体 SDF 是单通道，MSDF 是三通道。需新建 shader：

// data/shader/qm_icon_msdf.frag
// 采样 MSDF 三通道，取 median 计算距离场

uniform vec3 u_Color;      // 染色（来自 SetColor）
uniform float u_Range;     // SDF 有效范围（px，由烘焙参数决定）

float median(vec3 msdf) {
    return max(min(msdf.r, msdf.g), min(max(msdf.r, msdf.g), msdf.b));
}

void main() {
    vec3 msdf = texture2D(u_ColorTexture, v_TexCoord).rgb;
    float sigDist = median(msdf) - 0.5;  // 中心 = 0

    // 将像素距离换算为屏幕空间，再做 smoothstep 抗锯齿
    float aa = fwidth(sigDist);           // 自适应像素密度
    float alpha = smoothstep(-aa, aa, sigDist);

    FragClr = vec4(u_Color, alpha);
}

现有 RenderIcon 用标准 quad 渲染（QuadsBegin + QuadsSetSubset）。改为绑定 MSDF shader：

主题色联动改 QmUiColor 后 accent 组件即时变色设置页改色 + Dogfood 目视

12.3 不在范围

  • 旧 UI 路径（m_QmNewUi == 0）——不改动旧开始菜单、旧 tab 颜色、旧布局
  • backdrop-filter 实时模糊（DDNet 管线不支持）
  • HUD 拖拽磁吸/碰撞（独立 feature）
  • 中文文本预热 / 字图集预扩容（独立优化）
  • spacing 8dp 强改（已否决）
  • DDNet 原生组件（DoScrollbarH 交互逻辑、DoEditBox 输入逻辑）——只接管绘制
