全局卡片架构：统一拖拽 + 让位动画 + 持久化

2026-06-29 · status: active · 来源：阶段 2 拖拽架构调研 + 让位动画实践 + 用户全局卡片持久化需求

现状问题：四套卡片实现并存（栖梦侧栏合批 / 单卡 underlay / Tclient deck / section_loader 通用层），两套拖拽范式（栖梦长按 0.3s / Tclient 已统一长按），两套持久化（QmSidebarCardOrder / qm_settings_card_order），让位动画框架在但效果不对（拖拽中 TargetRect 不变 → 无让位）。本规格定义全局统一架构。

1 · 设计目标

iPhone 主屏风拖拽 UX：长按 → 被拖卡跟手 + 其他卡实时让位（spring lerp）→ 松手归位 + 持久化。全局卡片管理：一套 Model 管所有设置页卡片，每页只筛选展示，拖拽改全局 → 跨页保留。

2 · 全局卡片 Model（核心）

2.1 统一注册表

所有设置页卡片注册到同一个 qm_card_order::CModel（已建，阶段 2 Step 1 产物）。每个卡片声明 {stableId, page, column, order}：

  • stableId：全局唯一（如 "qm:visual:card_appearance"、"tclient:visual-font-cursor"）
  • page：归属页面（"qmclient" / "tclient" / "ddnet" / "appearance"）
  • column：列（Left / Right / Full）
  • order：列内顺序

页面渲染时 Model.ColumnIndices(page, column) 筛选本页卡片。

2.2 持久化

单一 config qm_global_card_order（格式 id:page:col:order;），替代当前的 QmSidebarCardOrder + qm_settings_card_order 两套。CModel::Parse 容错（未知 id 跳过），CModel::Serialize 写入。每帧 str_comp cache 检测变化。

迁移：首次启动检测旧 QmSidebarCardOrder / qm_settings_card_order，合并到 qm_global_card_order。

用户发散："持久化是全局的，每个页面只是展示卡片，可以随意移动组合" — 本规格采纳：卡片是全局资源，页面是展示层（filter），拖拽改全局 → 所有页生效。

3 · 让位动画（iPhone 风）

3.1 当前问题

拖拽中 order 不变（只算 DropIndex）→ TargetRect 不变 → cache lerp 追赶自己 → offset=0 → 无让位。松手 CommitDropPreview 改 order → TargetRect 变 → 但下一帧非拖拽态 offset=0 → 跳变。

3.2 正确实现：拖拽中实时预览布局

UpdateDropPreview 不只算 DropIndex，而是生成一个预览布局（PreviewLayout）：

  1. 基于当前全局 Model + 被拖卡的新位置（DropColumn + DropIndex），计算每张卡片的预览 TargetRect
  2. 预览 TargetRect 写入 ModuleCards[i].m_TargetRect（不 commit 到 Model，只渲染层预览）
  3. AnimateModuleCardPositions lerp cache → 预览 TargetRect
  4. Column 偏移到 cache → 卡片在 lerp 中间位置（实时滑动让位）

松手 CommitDropPreview → Model.Move（commit 预览到真实数据）+ Serialize 落盘。

3.3 松手归位

松手后 m_pDragging=nullptr，但 松手帧仍保持 Column 偏移（offset 不立即归零，走 cache lerp 自然收敛到 TargetRect）。即松手后 offset 从当前 cache 值 lerp 到 0（约 10 帧 0.17s）。

实现：offset 不硬切 0，而是 offset *= (1-LerpT) lerp 到 0。

技术要点：预览布局计算需要在 UpdateDropPreview 中模拟 "如果被拖卡在 DropIndex 位置，其他卡的 rect 会怎样"。当前栖梦的 ColumnSplitX + 遍历 prev/next 逻辑可以复用，但需要输出每张卡的 TargetRect（不只是落点 line）。

4 · 统一拖拽架构

4.1 消除 section_loader 旧拖拽

Tclient 的 SSettingsCardDeckDragState / SettingsCardDeckCanStartDrag / BeginPress / TryPromotePress / MoveWithinColumn / DropIndexForHoveredItem / ApplyOrder / AutoScrollDelta 全部删除，栖梦的 SQmModuleDragState / HandleModuleDragState / UpdateDropPreview / CommitDropPreview / RenderDragGhost 泛化为公共拖拽层。

4.2 统一入口

新建 QmUi/QmCardDrag.h（纯函数模板，可 TDD）：

// 长按状态机
struct SCardDragState<TCardId> {
    TCardId m_PressedId, m_DraggingId;
    float m_PressStartTime;
    vec2 m_GrabOffset;
};

// 长按晋升（每卡调用）
void HandlePressPromote(state, card, now, holdSec, mouseDown);

// 预览布局（每帧，输出每卡预览 TargetRect）
struct SDropPreview { int targetColumn, dropIndex; ... };
SDropPreview ComputeDropPreview(cards, mouseX, mouseY, columnSplitX);

// 让位 lerp（每帧）
void LerpDisplayRects(cache, targetRects, draggingId, mouseX, mouseY, lerpT);

4.3 保留 Tclient 独有价值

SettingsCardDeckAutoScrollDelta（边缘自动滚动，栖梦无）→ 并入公共拖拽层。

5 · 视觉统一（阶段 4 复用）

所有设置页卡片统一到 ui_widget::DrawCard（QmUi/UiContainers.h），消除 RenderQmSettingsGlassCard underlay + 栖梦合批的视觉割裂。SQmSettingsCardStyle 基于 ui_token:: 派生。

7 · 约束

  • 不改 DDNet 上游协议 / 物理 / 预测 / 碰撞
  • QmClient 配置项统一 qm_ 前缀
  • 拖拽触发统一长按 0.3s（已实现，不用 Ctrl）
  • section_loader.h 只保留渲染层（渐进渲染 + section 管理），拖拽逻辑全删
  • 全局 Model 是唯一持久化权威，旧 config 一次性迁移后废弃
