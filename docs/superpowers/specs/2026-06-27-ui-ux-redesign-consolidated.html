0 · 设计哲学与硬约束

本规格是 QmClient 新 UI（g_Config.m_QmNewUi != 0）的结构性重组。视觉参考 macOS 桌面（窗口层级、侧边栏、工具栏、source list、popover/sheet、可调 material 透明度、用户主题色）。解决三个核心问题：① 设置页 tab 过多且语义混乱（15 扁平 tab + QmClient 5 子 tab）；② 顶部导航栏缺乏左右分区；③ 组件库不完整（缺搜索框/下拉框/分段控件/颜色选择器），图标库质量差。

0.1 硬约束（不可突破）

  • DoButtonLogic / HotItem / ActiveItem 不动——交互判定是基石
  • 不引入运行时第三方库（SDF/MSDF 图标走构建期烘焙，Phosphor SVG 作为构建期输入）
  • 不改 DDNet 上游协议 / 物理 / 预测 / 碰撞
  • 新增文件仅落 src/game/client/QmUi/、src/game/client/components/qmclient/、data/shader/、data/qmclient/icons/、qmclient_scripts/
  • QmClient 配置项统一用 qm_ / Qm 前缀
  • 所有改动仅限 g_Config.m_QmNewUi != 0 新 UI 路径，旧 UI 路径不动
旧 UI 唯一例外（P-oldui）：旧 UI 顶部导航栏高度被 QmClient 从原版 24.0px 改成 34.0px（menus.cpp:285/2844/2948/5077），导致字体比 BestClient/原版大 50%。此修复仅限 menubar 高度这一个数值（34.0→24.0，或折中 28.0，待确认），详见附录 B。

1 · 主题系统：QmThemeRuntime

现状最大脱节：QmClient 已有完整主题色配置 g_Config.m_QmUiColor（默认 0xE4A046 琥珀色），用户可在设置页用 ColorPicker 自由修改。DDNet 原生菜单已全面接入（menus.cpp:124 的 MenuUiColorSurface/MenuUiColorAccent 等）。但 QmUi 组件层完全没接入——UiTokens.h 的 ACCENT_PRIMARY 是硬编码 #66C2F5，与用户配置毫无关系。

1.1 现有主题色管线（已成熟）

// menus.cpp:122-143 — 一个 m_QmUiColor HSLA 色码衍生出 surface/accent/hover/dim 全套
ColorRGBA MenuUiColorSurface(float AlphaScale, float ColorScale) {
    ColorHSLA UiHsla(g_Config.m_QmUiColor);
    UiHsla = UiHsla.UnclampLighting(0.42f);       // 统一亮度
    const ColorRGBA UiColor = color_cast<...>(UiHsla);
    return ColorRGBA(UiColor.r * ColorScale, UiColor.g * ColorScale,
                     UiColor.b * ColorScale, UiColor.a * UiAlpha * AlphaScale);
}

1.5 macOS material 透明度控制

macOS 提供 Reduce Transparency 与多层 material 语义。QmClient 已有 QmUiOpacity（0-100），当前仅影响 DDNet 原生面板。扩展方案：

配置项当前用途扩展用途
QmUiOpacityDDNet 原生面板 alpha（menus.cpp:128）同时驱动 QmUi material surface 的 alpha（MaterialSurface() 内已含 UiAlpha）

用户降低透明度时，material 表面变得更不透明（更接近 macOS 的 "reduced-transparency" 高对比模式），提升文字可读性。这是对 macOS Reduce Transparency 的等价映射。

2.2 L0 Root Panel — 设置页整体卡片化

现状：设置页导航栏（TabBar）和内容区是两个独立矩形，各自 Draw 各自 Margin，之间有 10px 缝隙，无外部呼吸边距，内容紧贴屏幕边缘。

目标：导航栏 + 内容区合并为一个统一面板，外围留呼吸边距（20pt），内部用分隔线区分导航和内容。

CUIRect RootPanel = Screen;
RootPanel.Margin(20.0f, &RootPanel);           // 外呼吸边距
qm_theme_runtime::DrawRootPanel(RootPanel);    // 统一 material 面板
CUIRect Nav, Content;
RootPanel.VSplitRight(TabBarWidth, &Content, &Nav);
// 分隔线而非两个独立卡片
CUIRect Divider; Content.VSplitRight(0.5f, &Content, &Divider);
Divider.Draw(BORDER_SUBTLE, CORNER_NONE, 0.0f);
Content.Margin(16.0f, &Content); Nav.Margin(12.0f, &Nav);

7.3 运行时 SDF 采样渲染

// data/shader/qm_icon_msdf.frag — 采样 MSDF 三通道，取 median 计算距离场
uniform vec3 u_Color; uniform float u_Range;
float median(vec3 msdf){ return max(min(msdf.r,msdf.g), min(max(msdf.r,msdf.g), msdf.b)); }
void main() {
    vec3 msdf = texture2D(u_ColorTexture, v_TexCoord).rgb;
    float sigDist = median(msdf) - 0.5;
    float aa = fwidth(sigDist);              // 自适应像素密度
    float alpha = smoothstep(-aa, aa, sigDist);
    FragClr = vec4(u_Color, alpha);
}

扩展 CQmIconManager::RenderIcon() 绑定 MSDF shader；EQmIcon 扩充到 40+，增加 EQmIconWeight 参数；manifest 加 "format":"msdf" + "sdfRange":4.0。Manifest 按 (icon, weight) 二维索引。

8 · SDF 抗锯齿圆角

CUIRect::Draw() → DrawRectExt()（graphics_threaded.cpp:1842）用 16 段三角扇（RECT_CORNER_SEGMENTS = 16）近似圆角，无 MSAA 时锯齿。SDF shader 可实现亚像素平滑。

8.1 短期：提高段数（零引擎改动）

一行常量改动：把 graphics_threaded.cpp:34 的 RECT_CORNER_SEGMENTS 从 16 提到 32 或 48，立刻减少圆角 faceting。QmClient 是 CPU 瓶颈非 fill-rate，顶点数 2-3× 可忽略。先于 SDF 圆角落地。

8.2 中期：SDF 圆角 shader

// data/shader/ui_sdf_rect.frag
float sdRoundRect(vec2 p, vec2 halfSize, float r) {
    vec2 q = abs(p) - halfSize + r;
    return min(max(q.x, q.y), 0.0) + length(max(q, 0.0)) - r;
}
void main() {
    vec2 center = v_LocalPos - u_RectSize * 0.5;
    float d = sdRoundRect(center, u_RectSize * 0.5, u_Radius);
    float aa = fwidth(d);
    float shape = 1.0 - smoothstep(-aa, aa, d);
    FragClr = vec4(u_Color.rgb, u_Color.a * shape);
}
前置：需 GL_OES_standard_derivatives（fwidth），确认 GLES 后端支持，否则降级固定 1px AA。渐进替换：仅 QmUi 组件层，不动全局 CUIRect::Draw()。与第 7 章共用同一条引擎 shader 注册通道。

9 · 图形与文本画质 2026-06-27 新增

背景：用户反馈 4K 显示器下皮肤/实体贴图"可感知的糊"、游戏内名字与战队文本糊（FSAA 无效）、UI 圆角锯齿。本章基于 2026-06-27 codegraph 代码级调研，给出针对 QmClient 实际渲染管线的画质方案。核心结论：QmClient 是 CPU 瓶颈的 2D 游戏，所有"降分辨率再超分"方案（DLSS/FSR/分辨率缩放）都是错的方向；糊的根因是资产分辨率低和文本采用位图采样而非 SDF。

原理：Real-ESRGAN 是开源 AI 超分模型，4× 放大同时脑补合理高频细节。"构建期离线"= 在开发者机器上跑一次，不是玩家运行时——玩家只是加载了更大的 PNG，零运行时开销。

# 256×128 → 1024×512，打包进游戏

9.3 方案 B：SDF 文本渲染（治文本糊根，FSAA 治不了的就靠它）第二优先

原理：把字体图集从"alpha 位图"改为"距离场"，text.frag 用 smoothstep(fwidth) 亚像素平滑——任意缩放/4K/相机 zoom 都锐利。业界标准做法（Valve 2007 SDF 论文，现代引擎标配）。

位图文本（现状）SDF 文本（目标）

实现要点：① 图集（已 2048²，text.cpp:311）改存距离场（FreeType 提供字形轮廓，用 msdfgen 或 EDT 算法生成）；② text.frag 改为 median + smoothstep；③ 描边（Grow()）改为距离场偏移。不碰引擎 shader 注册命门（text shader 已在用，只改内容），ROI 高。
