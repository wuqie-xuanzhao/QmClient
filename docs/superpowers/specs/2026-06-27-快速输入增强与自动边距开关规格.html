FastInput 模式增强 与 AutoMargin 开关

在 QmClient 已有的 TClient FastInput + AutoMargin 基础上，吸收 BestClient 的 best_input / saiko+ 输入模式，并给 AutoMargin 加开关。目标：让玩家可在「前推量 / 橡皮筋 / 延迟补偿」之间精细权衡，且 AutoMargin 与 LatencyComp 不再互踩。

① 目标 ② 现状 ③ 吸收项 ④ 配置项 ⑤ 实现 ⑥ 风险 ⑦ 验收 ⑧ 来源

① 目标与非目标

类型范围理由
目标给 AutoMargin 加开关 qm_auto_margin，关闭时 PredictionMargin 回退固定值。让 LatencyComp（best_input）与 AutoMargin 不再方向冲突，玩家可二选一。
目标吸收 BestClient 的 best_input(mode 3) 与 saiko+(mode 4) 模式。提供比 fast_input(mode 0) 更精细的前推控制（Smoothing/LatencyComp/Interpolation）。
目标PredictionMargin 集成 FastInputMargin：BaseMargin = max(cl_predictionmargin, FastInputMargin)。让 AutoMargin 感知 FastInput 前推量，防护协调（对齐 BestClient）。
非目标不改变默认行为：mode 0 + AutoMargin 开 = 当前现状。保证老玩家无感升级。
禁止不修改 demo 格式、网络协议、服务器端玩法语义。CLAUDE.md 硬约束；本规格只动客户端预测时序的可见参数。

② 现状（QmClient 已实现，调研确认）

能力状态实现
FastInput 基础（mode 0）已有tc_fast_input + tclient/fast_practice.cpp(2960 行) + client.cpp:3571 立即重预测 + SmoothTick += FastInputTicks 前推
AutoMargin（自适应缓冲）已有client.cpp:6431 PredictionMargin()，按实时延迟/抖动单向向上加缓冲；无条件启用，无开关
PredictionMarginState已有三态 STABLE/UNSTABLE/IGNORED_SPIKE + hud.cpp:95 颜色 + HUD 显示
PredictionMargin 集成 FastInputMargin缺失QmClient 的 PredictionMargin 不含 FastInput 前推量（与 BestClient 不同）
best_input / saiko+ 模式缺失无 bc_fast_input_mode 等价物，只有 mode 0
AutoMargin 开关缺失无开关，无法与 LatencyComp 解耦
关键认知修正（调研过程）：FastInput 与 AutoMargin 是正交两维——FastInput 管「输入响应速度 + 视觉前推」，AutoMargin 管「预测总距离/向上缓冲」。QmClient 已是双向系统，本规格是增强调参维度，不是补缺口。

③ 吸收项（来自 BestClient）

3.1 AutoMargin 开关 qm_auto_margin

给 PredictionMargin() 加开关，对齐 BestClient bc_fast_input_auto_margin：

int CClient::PredictionMargin() const {
    if(!m_ServerCapabilities.m_SyncWeaponInput) return 10;
    const int BaseMargin = ...;  // 集成 FastInputMargin 后的 base（见 3.3）
    if(!g_Config.m_QmAutoMargin)               // ← 新增开关
        return std::clamp(BaseMargin, 1, 300);  // 关闭：固定值，不做自适应
    // ... 原有 AutoMargin（Excess/Jitter/Problems）逻辑 ...
}

3.2 FastInput 模式 qm_fast_input_mode（0/3/4）

吸收 BestClient EffectiveFastInputOffsetTicks（fast_practice.cpp:56-100）的三模式分支：

模式前推公式调节维度
0 = Fast inputtc_fast_input_amount / 20.01（amount，ms）
3 = Best inputoffset/100 × (1−smoothing/200) × (1+latency_comp/100)3（offset + smoothing + latency_comp）+ interpolation
4 = Saiko+saiko_plus_amount / 100.0，ceil(offset+1.0)1（amount，0.01 tick 细粒度）

3.3 PredictionMargin 集成 FastInputMargin

对齐 BestClient client.cpp:5924，把 FastInput 前推量算进 BaseMargin：

int FastInputMargin = 0;
if(g_Config.m_TcFastInput) {
    const int Mode = QmFastInputNormalizedMode(g_Config.m_QmFastInputMode);
    if(Mode == 0)      FastInputMargin = std::max(0, g_Config.m_TcFastInputAmount);
    else if(Mode == 4) FastInputMargin = (std::max(0, g_Config.m_QmSaikoPlusAmount) + 2) / 5;
    else               FastInputMargin = (std::max(0, g_Config.m_QmBestInputOffset) + 2) / 5;
}
const int BaseMargin = std::max(g_Config.m_ClPredictionMargin, FastInputMargin);

⑥ 风险与权衡

风险说明对策
LatencyComp ↔ AutoMargin 方向冲突两者都「延迟高时调整」：AutoMargin 加缓冲（向上），LatencyComp 加前推（向前），叠加会互踩。qm_auto_margin 开关让玩家二选一；UI 在启用 LatencyComp 时提示可关 AutoMargin。
预测时序回归动 PredictionMargin / FastInput 影响所有玩家的输入手感与橡皮筋。默认值=现状（mode 0 + auto_margin on + 各参数 0）；gate 全量；预测路径 review。
橡皮筋加剧mode 3/4 前推更大，弱网下服务器纠正偏差更明显。Smoothing 参数专门缓解；MaxLatencyTicks 重置 + predTick 范围检查已有防护。
UI 复杂度3 模式 × 多参数，普通玩家难调。mode 0 保持默认；高级参数折叠；给推荐预设（如「弱网稳」= Smoothing 高 + AutoMargin on）。
