# 构建选项

> 对应上游：`docs/BUILDING.md`

基础构建说明请参阅 [README 中的 Building 章节](/README.md)。

以下是可传给 `cmake` 命令行工具的部分构建参数（非穷举），用于在构建期启用或关闭各项功能：

* **-DCMAKE_BUILD_TYPE=[Release|Debug|RelWithDebInfo|MinSizeRel]** <br>
	可选的 CMake 变量，用于设置构建类型。若未设置，当**未**使用 `-DDEV=ON` 时默认为 "Release"，使用 `-DDEV=ON` 时默认为 "Debug"。更多信息见 CMake 文档中的 `CMAKE_BUILD_TYPE`。

* **-DPREFER_BUNDLED_LIBS=[ON|OFF]** <br>
	是否优先使用内置库而非系统库。设为 ON 会让 DDNet 使用 `ddnet-libs` 文件夹中可用的第三方库（该文件夹是 [ddnet-libs](https://github.com/ddnet/ddnet-libs) 仓库的 git submodule 目标）——当系统未安装这些库、又想避免自行构建时很有用。若设为 OFF，则仅在找不到系统库时才使用内置库。默认值 OFF。

* **-DWEBSOCKETS=[ON|OFF]** <br>
	是否为服务端启用 WebSocket 支持。设为 ON 需要安装 `libwebsockets-dev` 库。默认值 OFF。

* **-DMYSQL=[ON|OFF]** <br>
	是否为服务端启用 MySQL/MariaDB 支持。至少需要 MySQL 8.0 或 MariaDB 10.2。设为 ON 需要安装 `libmariadb-dev-compat` 库，常见平台也提供了对应的内置库。默认值 OFF。

	注意：内置的 MySQL 库在你的系统上可能无法正常工作。如果连接 MySQL 服务器时出现问题（例如你选择了其他用户却以 root 连接），请确保安装系统自带的 MySQL 客户端库。确认 CMake 配置摘要显示它找到的是**非内置**的 MySQL 库（没有出现 "using bundled libs"）。

* **-DTEST_MYSQL=[ON|OFF]** <br>
	是否在基于 GTest 的测试中测试 MySQL/MariaDB 支持。默认值 OFF。

	注意：这要求在 localhost 上运行 MySQL/MariaDB，并按如下方式配置：

```sql
CREATE DATABASE ddnet;
CREATE USER 'ddnet'@'localhost' IDENTIFIED BY 'thebestpassword';
GRANT ALL PRIVILEGES ON ddnet.* TO 'ddnet'@'localhost';
FLUSH PRIVILEGES;
```

* **-DAUTOUPDATE=[ON|OFF]** <br>
	是否启用自动更新器。打包者可能希望在自己的包中关闭它。Windows 和 Linux 上默认值 ON。

* **-DCLIENT=[ON|OFF]** <br>
	是否启用客户端编译。若设为 OFF，DDNet 将不依赖 Curl、Freetype、Ogg、Opus、Opusfile 和 SDL2。默认值 ON。

* **-DVIDEORECORDER=[ON|OFF]** <br>
	是否在客户端中加入基于 FFmpeg 的视频录制支持。默认值 ON。

* **-DDOWNLOAD_GTEST=[ON|OFF]** <br>
	是否下载并编译 GTest。当系统未安装 GTest，且 Linux 用户找不到合适软件包时有用。默认值 OFF。

* **-DDEV=[ON|OFF]** <br>
	是否为开发做优化，略微加快编译过程。启用后不生成打包所需内容。设为 ON 会将 CMAKE\_BUILD\_TYPE 默认设为 Debug。默认值 OFF。

* **-DUPNP=[ON|OFF]** <br>
	是否为服务端启用 UPnP 支持。
	Debian 上需安装 `libminiupnpc-dev`，Arch Linux 上需安装 `miniupnpc`。
	默认值 OFF。

* **-DVULKAN=[ON|OFF]** <br>
	是否启用 Vulkan 图形后端。
	需要安装 [Vulkan SDK](https://vulkan.lunarg.com/sdk/home) 并相应设置 `VULKAN_SDK` 环境变量。
	Linux 上默认值 ON，Windows 和 macOS 上默认值 OFF。

* **-GNinja** <br>
	使用 Ninja 构建系统替代 Make。它会自动并行化构建，通常更快。用 `ninja` 而非 `make` 编译。Debian 上用 `sudo apt install ninja-build` 安装 Ninja，Arch Linux 上用 `sudo pacman -S --needed ninja`。

* **-DCMAKE_CXX_LINK_FLAGS=[FLAGS]** <br>
	链接时传给编译器的自定义标志。

* **-DEXCEPTION_HANDLING=[ON|OFF]** <br>
	启用异常处理（目前仅在 Windows 上有效，在那里使用 DrMingw）。默认值 OFF。

* **-DIPO=[ON|OFF]** <br>
	启用过程间优化，也称链接时优化（LTO）。默认值 OFF。

* **-DPRECOMPILE_HEADERS=[ON|OFF]** <br>
	预编译常用头文件以加速编译。需要 CMake 3.16。默认值 ON。

* **-DFUSE_LD=[OFF|LINKER]** <br>
	指定使用的链接器。默认值 OFF，会依次尝试 mold、lld、gold。

* **-DSECURITY_COMPILER_FLAGS=[ON|OFF]** <br>
	是否设置安全相关的编译器标志，如 `-D_FORTIFY_SOURCE=2` 和 `-fstack-protector-all`。默认值 ON。

* **-DMACOS_CODESIGN=[ON|OFF]** <br>
	在 macOS 上构建 DMG 时是否对代码签名。

## 在 Linux 上交叉编译到 Windows x86/x86\_64

安装形如 `i686-w64-mingw32-gcc`（32 位）或 `x86_64-w64-mingw32-gcc`（64 位）的 MinGW 交叉编译器。这大概是最难的部分。；)

然后在**首次** CMake 命令行中加入 `-DCMAKE_TOOLCHAIN_FILE=../cmake/toolchains/mingw64.toolchain`。

## 在 Linux 上交叉编译到 macOS

安装 [osxcross](https://github.com/tpoechtrager/osxcross)，然后在**首次** CMake 命令行中加入 `-DCMAKE_TOOLCHAIN_FILE=../cmake/toolchains/darwin.toolchain` 和 `-DCMAKE_OSX_SYSROOT=/path/to/osxcross/target/SDK/MacOSX10.11.sdk/`。

从 [libdmg-hfsplus](https://github.com/mozilla/libdmg-hfsplus) 安装 `dmg` 和 `hfsplus`，并从 [diskdev\_cmds](http://pkgs.fedoraproject.org/repo/pkgs/hfsplus-tools/diskdev_cmds-540.1.linux3.tar.gz/0435afc389b919027b69616ad1b05709/diskdev_cmds-540.1.linux3.tar.gz) 安装 `newfs_hfs`，以解锁输出 macOS 磁盘映像的 `package_dmg` 目标。
