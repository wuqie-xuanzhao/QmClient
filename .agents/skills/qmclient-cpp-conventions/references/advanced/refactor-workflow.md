# 重构工作流

本文件用于行为保持型重构。重构的目标是降低复杂度、风险或维护成本，不是顺手现代化，也不是扩大功能。

## 准入条件

允许重构：

- 已有代码阻碍当前任务理解或验证。
- review finding 明确指出结构、重复或热路径问题。
- 性能量化证据指向某个局部热点。
- 需要为测试、日志或安全边界建立小型 seam。

不允许重构：

- 没有当前任务收益的风格清理。
- 为了个人偏好改 DDNet 既有模式。
- 大范围重写上游代码。
- 未经批准改变协议、demo/skin/map 格式、物理、预测或玩法语义。

## 行为边界

重构前必须写清楚：

- 哪些 public 行为不变。
- 哪些日志字段、配置键、UI 文案或顺序不变。
- 哪些文件和模块不碰。
- 哪些测试能证明行为边界。

如果说不清边界，先探索，不要改。

## 执行方式

- 一次只做一个重构动作：抽函数、收窄 helper、统一常量、删除重复逻辑、改名。
- 每步后跑聚焦验证。
- 不把 bugfix、feature 和大重构混在同一 patch。
- 抽象只在真实减少重复或降低风险时引入。
- 文件中已有用户改动时，先理解并适配，不要回退。

## 验收

重构完成时必须说明：

- 复杂度或重复在哪里下降。
- 外部行为如何保持。
- 跑了哪些测试和 gate。
- 哪些建议被延后，为什么不属于本轮。
