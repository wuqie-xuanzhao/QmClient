# 特性引入工作流

本文件用于新增功能、配置、UI 行为、用户可见能力或较大交互变化。

## 准入问题

新增特性前先回答：

- 用户问题是什么，是否有日志、反馈或现有缺口支持。
- 是否能用现有功能、配置或文档解决。
- 是否影响 DDNet 兼容性、玩法、公平性、协议、demo、skin、map 或配置格式。
- 默认开启还是默认关闭；是否需要回滚开关。
- 是否会增加主线程、内存、网络或磁盘成本。

缺少明确问题时，不进入实现。

## 设计要求

- 新配置使用 `qm_` / `Qm` 前缀。
- 新功能默认不应破坏官方 DDNet 行为。
- 新 UI 不和性能优化混为一轮，除非性能系统证明 UI 本身是问题。
- 新后台任务必须定义取消、预算、发布和 fallback。
- 新文件格式或序列化变化需要明确批准。

## 分阶段策略

1. 先做可观测性或最小行为。
2. 再加用户可见控制。
3. 最后做自动化、默认策略或更大范围接线。

不要用“以后会扩展”作为本轮引入大抽象的理由。

## 验收

新特性完成时至少有：

- 需求或设计文档。
- 行为测试或源码合同测试。
- 配置项使用检查。
- 对性能、内存、安全和兼容性的简短结论。
- 回滚或禁用方式，除非功能天然不可配置且低风险。
